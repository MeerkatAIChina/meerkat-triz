# Meerkat-TRIZ-v1 发布：TRIZ 领域首个 LLM 微调模型，以及让它保持诚实的评测基础设施

*Meerkat AI · 2026 年 7 月*

## TRIZ 是什么

TRIZ（俄文"发明问题解决理论"缩写）由根里奇·阿奇舒勒及其同事自 1946 年起，从对数十万件专利的分析中提炼而成。它的核心洞察是：**创新不是随机的天才灵光**——同样的技术问题在不同行业反复出现，而它们的解法遵循可复用的模式。航空领域 1975 年解决的问题，可能就是今天电池工程师面对的同一个矛盾。

它的工具箱在"创造力方法"里罕见地结构化：解决技术矛盾（改善一个参数而不恶化另一个）的 **40 个有编号的发明原理**与矛盾矩阵；处理物理矛盾的**分离原理**；重构和求解难题的完整算法 **ARIZ**；以及用于路线图思考的技术系统进化法则。三星、西门子、GE、波音都曾用它对数以千计的工程师做内训；在中国，TRIZ 是国家创新方法推广工作的组成部分。

问题是：这套方法论今天几乎只存在于昂贵的培训课程和持证咨询师身上。

## 为什么值得为 TRIZ 做微调

TRIZ 不是零散知识，而是一套有严格结构的创新操作系统：40 个有编号的发明原理、标准化的矛盾分析流程、完整的 ARIZ 算法。但这套方法论今天的分发方式极原始——主要靠考证培训和咨询：一家企业的 TRIZ 能力，约等于它养得起几个持证专家；全球活跃 TRIZ 咨询师是千人量级，而需要这套方法论的工程师是百万量级。

此前的 LLM+TRIZ 工作全部是提示词工程。微调能买到三样提示词买不到的东西：**术语纪律**（原理编号引用、分析步骤完整性，固化进权重而不是在 prompt 里恳求）、**行为风格**（直接可执行的回答而非冗长思考流——我们的微调把基座回答压缩到约 1/10 长度且覆盖持平）、**能力内嵌**（"查书答题"与"学会方法"的区别，在生成类任务上最明显）。

微调模型把方法论的应用能力从按人天计费的服务，变成边际成本为零的基础设施。这就是这次发布的赌注。

## TRIZ 微调模型对企业创新的基础作用

企业创新的瓶颈往往不是点子——而是**问题表述**。大多数工程团队早在创意阶段之前就卡住了：他们说不清自己真正面对的矛盾是什么。这恰恰是 TRIZ 的价值所在，也恰恰是常驻模型能帮上忙的地方：

- **在需要的时刻在场。** 培训课上学到的方法论会随时间衰减；而工位上的模型能在设计评审前夜凌晨两点回答"我的这个矛盾该用哪几条原理"，而不是等到下个季度的培训营。
- **入门层的规模化。** 我们最强的任务类型恰是 principle_recommendation 与 concept_explanation——正是入门普及层。"让每个工程师具备方法论素养"的成本，从培训项目级的预算条目降为一次 API 调用。
- **成为专家的初稿层。** 矛盾分析、ARIZ 引导报告由模型起草、咨询师把关——专家时间从"生产"转移到"判断"。

边界也要说清楚：这是助手，不是替代。复杂的创新项目仍然需要人类咨询师。改变的是下限——每个工程师都有了一位懂方法论的同事，专家则获得了杠杆。

今天我们发布三样东西：

- 🤖 **[Meerkat-TRIZ-v1](https://huggingface.co/Meerkat-AI/Meerkat-TRIZ-v1)**——在 Qwen3.6-35B-A3B 上微调的 LoRA 适配器（181MB，可训练参数 0.24%），面向中文 TRIZ（发明问题解决理论）问答。据我们所知，这是 TRIZ 领域首个公开发布的 LLM 微调模型。
- 📊 **[triz-gold-benchmark](https://huggingface.co/datasets/Meerkat-AI/triz-gold-benchmark)**——双金标评测基准（100 + 300 题），覆盖六类 TRIZ 任务。
- 🛠️ **[meerkat-triz](https://github.com/coidea-sys/meerkat-triz)**——迭代过程中沉淀的评测 harness，下文每一条教训都被固化为机检断言。另有[中英双语白皮书](https://github.com/coidea-sys/meerkat-triz/blob/main/docs/WHITEPAPER.zh-CN.md)（[English](https://github.com/coidea-sys/meerkat-triz/blob/main/docs/WHITEPAPER.md)）。

## 结果——全部结果，包括打平的那个

在原生 v5 金标口径（300 题，逐题配对统计）：

- **judge 轨：相对基座 +0.09 ~ +0.10——三个外部评委中两个显著**（Claude Sonnet +0.094 [+0.020, +0.167]、GPT +0.104 [+0.020, +0.184]；Gemini −0.048 不显著），来自发布后终审：协议逐字复跑，仅换用三家外部厂商评委。我们的同族评委读数为 **+0.39** [+0.30, +0.49]——其中约 3/4 是评委家族效应，不得外推。
- **提升最大的是我们定向修复的那个：概念讲解子集，+0.24 / +0.31 / +0.29——三个外部评委下全部显著**（同族读数 +0.73）。
- **关键词轨：−0.0001——完全持平。** 模型与基座覆盖的期望术语一模一样。
- 在较早的 v4 口径（100 题）上，Meerkat-TRIZ-v1 与我们内部最强基线**统计打平**。这句话写在 model card 里、白皮书里，也写在这里。

我们未做外部模型对比，也不做任何此类宣称。上述终审改变的是**评委**而非被对比的模型——[完整报告](https://github.com/coidea-sys/meerkat-triz/blob/main/docs/EXTERNAL_JUDGE_REVIEW.zh-CN.md)。

## 为什么评测故事比 model card 更值得读

这个项目更有普适价值的部分，是评测系统在迭代中抓到的东西。三类故障，每一类都足以反转结论：

**1. 会说谎的基线（+1.00 → −0.30）。** 连续三个版本，我们的报告都显示微调相对基座提升将近一个 judge 分。是假的。harness 剥离了 thinking-native 基座所需的空 think 块；失去"思考已结束"锚点的基座，在 91/100 道金标题上输出未闭合的英文思考草稿——两条评分轨评的都是草稿。修复后，v4 对基座的差值反号为 **−0.30**。如果你在评测 thinking-native 模型，先检查你的 prompt 渲染，再检查其他一切。

**2. 评委位置偏差达文献振幅两倍。** 我们的 pairwise 评委有 81% 的概率选择放在第二位的候选——位置不一致率 0.87，而文献报告的摆动约 25pp。此场景下任何单序 pairwise 结论都是噪声。双序合并由此成为唯一有效口径并以代码强制。（另有一个独立发现：评委在温度 0 下**完全确定**，重复翻转率 0.000——这正是"钉版评委 + 单次运行"协议站得住的原因。）

**3. 两条轨投出相反的票。** 关键词命中率与 LLM 评委分仅共享约 10% 方差。迭代中两轨曾显著反向：v3 关键词轨显著更好（+0.056）、judge 轨显著更差（−0.068）——它学会了堆关键词，语义质量反而下降。由此沉淀的规则：**发布门必须双轨，任何单轨结论不得独立下判。**

**4.（发布后量化）评委是自家人。** 我们早把"评委与数据生成器同族"声明为局限——但声明不能校准数字。于是发布后我们把整套评委协议换三个外部评委复跑：方向保住了（2/3 显著），量级没保住——外部估计只有同族 +0.39 的约 1/4。三个外部评委互相 Spearman 0.63–0.75，但与我们的同族评委仅 0.27–0.31——这是系统性的评分尺度差异，不是噪声。如果你的评委和数据生成器同族，上头条数字之前先为这一项留出预算。

## 微调究竟带来了什么

在干净锚点下，早期微调的真实故事是行为压缩：think 式长作答（约 3,250 字符）变为约 1/10 长度的直接作答，关键词覆盖持平，judge 轨质量略低于冗长的基座。Meerkat-TRIZ-v1 是首个把这种压缩转化为原生口径 judge 轨真实增益的版本——同时在旧口径上仍仅与 v2 打平。两个事实都在 model card 里。

## 局限，如实声明

单领域（中文 TRIZ 问答）、单基座、单 PEFT 配置。评委与数据生成器同族（已声明"同族弱异源"；发布后异源终审在 2/3 外部评委下确认方向、量级约为同族读数 1/4——同族分数不可跨评委家族外推；一个外部评委对原理推荐子集给出显著负差，单一评委支持，正在跟进）。100 题口径的子集结论仅为描述性。公开基准因版权原因不含参考答案——关键词轨可完整复现，judge 轨绝对分不可。
