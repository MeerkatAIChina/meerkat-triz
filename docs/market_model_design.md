# 数字孪生 · 市场模型构建指南

> Meerkat-DT 的核心子模型。市场模型回答一个问题：**"决策动作 → 市场反应"**（调价后销量怎么变、选品能不能卖、投放 ROI 怎么变）。本指南给出从数据到模型到验证的完整构建方法，从最核心的"价格弹性"切入。

## 一、市场模型的目标与边界

**核心目标**：预测"如果我做 X，市场会怎样反应 Y"。

| 决策 X | 要预测的 Y | 关键模型 |
|---|---|---|
| 调价 | 销量、GMV、毛利 | 价格弹性模型 |
| 选品/新品 | 新品销量、生命周期 | 需求预测 + 类比模型 |
| 投放 | 曝光、转化、ROI | 广告响应模型 |

**边界**：市场模型不预测"大盘黑天鹅"（疫情、政策），只预测"我的动作 → 我的结果"。大盘变化作为外生输入。

## 二、三层架构（统计精确 + ML 预测 + LLM 推演）

```
第1层 数据层：本店价格/销量/GMV + 竞品价格 + 大盘趋势
    ↓
第2层 统计模型层：价格弹性（log-log回归）+ 需求预测（时间序列）
    ↓
第3层 LLM 推演层：软信息融合（竞品策略/大促/政策）
```

**关键原则**：**统计模型做精确的数值预测，LLM 做统计模型看不到的"软信息"补充**。不要让 LLM 直接预测数字（会幻觉），让它判断"趋势和策略"。

## 三、价格弹性模型（最核心，从调价切入）

### 3.1 什么是价格弹性

```
价格弹性 ε = 销量变化% ÷ 价格变化%
ε = -2 表示：降价 10% → 销量涨 20%
|ε| > 1 弹性大（适合促销）
|ε| < 1 弹性小（降价不划算）
```

### 3.2 数据需求

| 数据 | 粒度 | 最少历史 |
|---|---|---|
| 本店价格、销量、GMV | 天级 | 90 天 |
| 竞品价格 | 天级（监控） | 90 天 |
| 促销标记（是否打折/大促） | 天级 | 90 天 |
| 季节/时段哑变量 | — | — |

### 3.3 建模方法：log-log 回归

**公式**：

```
log(销量) = β₀ + β₁·log(价格) + β₂·log(竞品价格) + β₃·促销哑变量 + β₄·季节哑变量 + ε
```

其中 **β₁ 就是价格弹性系数**（负值，因为价涨量跌）。

**为什么用 log-log**：β₁ 直接就是弹性（百分比关系），且能处理"价格翻倍销量减半"这类非线性关系。

### 3.4 关键：分细分市场分别拟合

**不同品类/价格带/时段的弹性差异极大**，不能全局一个弹性：

```
家电类：弹性 -1.5（价格敏感）
美妆类：弹性 -0.8（品牌忠诚度高）
日用品：弹性 -0.3（刚需，不敏感）

大促期间：弹性放大 2-3 倍
平时：弹性较小
```

所以必须**分组拟合**：
- 按品类分组
- 按价格带分组（高端 vs 平价）
- 按时段分组（大促 vs 平时）

### 3.5 实现代码框架

```python
import pandas as pd
import statsmodels.api as sm

def fit_price_elasticity(df, category):
    """对某品类拟合价格弹性。
    df: 含 log_price, log_competitor_price, promo_flag, season_flag, log_sales
    """
    X = df[["log_price", "log_competitor_price", "promo_flag", "season_flag"]]
    X = sm.add_constant(X)
    y = df["log_sales"]
    model = sm.OLS(y, X).fit()
    elasticity = model.params["log_price"]  # 价格弹性系数
    return {"elasticity": elasticity, "model": model, "r2": model.rsquared}

# 使用：预测"调价 -10% 后销量变化"
def predict_sales_change(elasticity, price_change_pct):
    return elasticity * price_change_pct  # 销量变化百分比
```

### 3.6 模型验证（关键，否则孪生不可信）

**验证一：留出测试**
- 用前 70% 数据拟合，后 30% 数据验证预测准确性
- 看预测销量 vs 实际销量的误差（MAPE）

**验证二：真实调价对比**
- 每次真实调价后，记录"模型预测的销量变化" vs "实际销量变化"
- 偏差持续超过 30% → 弹性模型需要重新拟合或加入新变量

**验证三：分品类抽查**
- 人工抽查几个品类，看弹性是否符合商业直觉（如日用品弹性应该小）

## 四、需求预测模型（选品/补货的基础）

### 4.1 方法：时间序列分解

```
销量 = 趋势(Trend) + 季节(Seasonal) + 周期(Cycle) + 随机(Noise)
```

用 STL 分解或 Prophet，把销量拆成四部分，分别预测再合并。

### 4.2 新品需求预测（最难）

新品没有历史数据，用**类比法**：
- 找 3-5 个"相似商品"（同品类、同价格带、同人群）
- 用相似商品的历史销量曲线，作为新品的初始预测
- 上市后 2 周内，用真实数据快速校准

## 五、竞品模型

竞品行为是市场模型的关键外生变量：

| 竞品动作 | 对孪生的影响 |
|---|---|
| 竞品降价 | 我店销量流失，价格弹性中的 log_competitor_price 体现 |
| 竞品上新 | 市场份额变化，需 LLM 判断影响 |
| 竞品大促 | 短期流量分流 |

**建模**：竞品价格作为回归变量（已有），竞品"上新/大促"等事件由 LLM 判断并作为哑变量注入。

## 六、LLM 推演引擎的角色（关键：LLM 不预测数字）

LLM 在市场模型中的**三个正确用法**：

### 用法 1：软信息判断（统计模型看不到的）
```
统计模型：过去 90 天价格弹性 -1.5
LLM 判断：竞品下周要上新（新闻/行业情报）→ 弹性可能暂时失效
→ 推演时把 LLM 的判断作为"弹性调整因子"
```

### 用法 2：多方案推演（模拟）
```
LLM 拿到统计模型的弹性参数，推演：
- 方案 A：降 5%，预测销量 +7.5%，毛利 -2%
- 方案 B：降 10%，预测销量 +15%，毛利 -8%，但可能触发竞品跟降
→ LLM 综合推演，输出各方案的"未来图景"
```

### 用法 3：异常补充
```
统计模型预测"调价 -10% → 销量 +15%"
但实际 +5% → 偏差 10%
LLM 反思：为什么？可能竞品同期也降价了 → 校准竞品参数
```

**核心纪律**：**LLM 不直接输出销量数字，而是基于统计模型的参数做推演，并补充软信息**。这样既用了 LLM 的推理能力，又避免了 LLM 幻觉数字。

## 七、市场模型的构建里程碑

| 阶段 | 产出 | 时间 |
|---|---|---|
| 1 | 价格弹性模型（调价场景，3-5 个核心品类） | 2-3 周 |
| 2 | 需求预测（时间序列） | 2-3 周 |
| 3 | 竞品监控 + LLM 软信息融合 | 1 个月 |
| 4 | 新品类比模型 | 1-2 个月 |
| 5 | 全品类覆盖 + 持续校准 | 持续 |

## 八、市场模型的健康指标

模型是否可信，监控三个指标：

| 指标 | 健康标准 |
|---|---|
| 预测准确率（MAPE） | < 20%（调价场景） |
| 弹性稳定性 | 弹性系数月度波动 < 30% |
| 校准偏差 | 真实结果 vs 预测持续偏差 < 30% |

**偏差持续超阈值 → 模型失效，回退到"规则引擎 + 人工决策"，不强行用错误孪生。**

## 九、一句话总结

**市场模型的构建核心是"分细分市场的价格弹性"（log-log 回归，按品类/价格带/时段分组拟合），用留出测试和真实调价对比验证；LLM 不预测数字，而是基于统计参数做多方案推演 + 补充竞品/大促等软信息。关键纪律：模型偏差超阈值就回退人工，绝不用错误的孪生做决策。**
