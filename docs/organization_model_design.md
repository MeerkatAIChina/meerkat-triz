# 数字孪生 · 组织模型构建指南

> Meerkat-DT 四层模型的最后一层。前三层（市场/供应链/顾客）是"外部业务模型"，组织模型是"内部运作模型"——回答一个核心问题：**"AI 的决策，经过 600 人的组织，多久能落地、落地时是否走样"**。

## 一、目标与边界

**核心目标**：模拟"决策 → 组织流转 → 执行"的完整过程，量化三个损耗：

| 损耗 | 含义 | 电商场景 |
|---|---|---|
| **决策延迟** | 决策到执行要多久 | AI 建议补货 → 人工审批 → 下单，可能 2 小时 |
| **执行偏差** | 执行时是否走样 | AI 建议降价 5%，人实际降了 8%（加了主观判断） |
| **信息损耗** | 战略意图传递失真 | 总监"提升转化"→ 传到执行变成"打折促销"（指令衰减） |

**边界**：组织模型不模拟"人的情绪/政治斗争"，只模拟"决策流转的结构性延迟和损耗"。

## 二、组织结构模型（600 人的分层）

```
决策指挥层（50人）：品类负责人、运营总监——审批 AI 建议
    ↓ 决策流转
数据分析层（100人）：分析师——校验数据、补充上下文
    ↓ 执行指令
执行运营层（400人）：客服、仓储、投放执行——落地动作
    ↓ 结果反馈
技术支撑层（50人）：数据管道、系统——保障闭环
```

**关键**：数字孪生把组织建模为**决策流转网络**，每个节点（人/角色）有"处理延迟"和"损耗系数"。

## 三、核心子模型

### 1. 决策流转模型（延迟的数学）

决策从 AI 到执行，经过 N 个环节，每环节有延迟：

```
总延迟 = Σ 各环节延迟
      = 审批延迟 + 传递延迟 + 执行延迟

补货场景：
AI 建议（0秒）→ 推送给负责人（10分钟）→ 负责人审批（30分钟，可能在看别的）
→ 下达执行（10分钟）→ 仓库下单（2小时）→ 总计约 3 小时
```

**数字孪生推演**：任何决策，先模拟"经过组织要多久"，识别"延迟是否会导致错过窗口"（如补货延迟导致断货）。

### 2. 执行偏差模型（损耗的数学）

人执行 AI 决策时，会加主观调整，产生偏差：

```
实际执行 = AI 建议 × (1 + 偏差系数)

偏差系数来源：
- 人加了自己的经验判断（如"这品类降价 5% 不够，我降 8%"）
- 信息理解偏差（如"提升转化"被理解成"降价"）
- 执行能力偏差（如仓库实际只发出 80% 的货）
```

**偏差系数用历史数据拟合**：对比"AI 建议"和"实际执行"，算出每类决策、每个角色的平均偏差。

### 3. 信息损耗模型（指令衰减）

这是猫鼬AI报告的"指令衰减"问题。战略意图在层级传递中失真：

```
总监意图："提升用户转化率"（正确）
    ↓ 传递给经理
经理理解："让用户多买"（开始走样）
    ↓ 传递给执行
执行理解："做促销打折"（完全走样——打折≠转化率）
```

**建模**：信息每经过一个层级，语义损耗系数（如 0.7），N 层后损耗 0.7^N。

### 4. 组织瓶颈模型（TRIZ 子系统不均衡进化）

组织进化的瓶颈是"最慢的环节"，用**排队论/瓶颈分析**识别：

```
哪个环节延迟最长、损耗最大 = 组织瓶颈

例子：
- 若"审批"是瓶颈（负责人太忙）→ 决策积压在审批环节
- 若"执行"是瓶颈（仓库处理慢）→ 决策下了但执行不了
```

**数字孪生的价值**：模拟"如果增加审批人手/自动化审批，整体延迟降多少"，量化组织改进的收益。

## 四、数据需求

| 数据 | 来源 | 说明 |
|---|---|---|
| 决策日志 | ecom/feedback_log | AI 建议 vs 实际执行（算偏差） |
| 审批时间戳 | 系统记录 | 决策到执行的时间（算延迟） |
| 组织架构/角色 | 人事系统 | 谁有权做什么（权限模型） |
| 执行结果 | 各平台 API | 实际动作 vs 预期（算偏差） |

**关键：决策日志是组织模型的数据金矿**——它已经记录了"AI 建议了什么、人实际做了什么、结果如何"，这正是计算"执行偏差"和"决策延迟"的原始数据。

## 五、LLM 的角色（组织模型里最大）

组织模型里 LLM 的价值独特：**LLM 是唯一能理解"人的隐性决策逻辑"的组件**。

| LLM 分析 | 作用 |
|---|---|
| 驳回理由挖掘 | 人驳回 AI 决策时填的理由，LLM 提炼"人看到了什么 AI 没看到的" |
| 指令衰减识别 | LLM 对比"总监意图"和"执行动作"，识别语义走样 |
| 组织瓶颈诊断 | LLM 从决策日志识别"哪个环节反复延迟/损耗" |
| 隐性知识蒸馏 | 把人的经验（驳回理由、调整原因）沉淀进孪生 |

**核心机制**：人的"驳回理由"和"执行调整"是最宝贵的隐性知识，LLM 持续蒸馏，让组织模型（以及整个孪生）越来越理解"组织真实怎么运作"。

## 六、组织模型的独特价值：让孪生"闭环"完整

四层模型的关系，组织模型是"粘合层"：

```
市场模型：预测"动作 → 销量"（外部）
供应链模型：预测"销量 → 库存"（外部）
顾客模型：预测"动作 → 用户价值"（外部）
组织模型：预测"决策 → 执行"的延迟和损耗（内部）← 粘合三层
```

**没有组织模型，前三层假设"决策立即、无损执行"**——这是致命的不现实假设。组织模型补上"延迟和损耗"，孪生才真正逼近现实：

```
完整推演 = 市场预测 × 组织执行偏差 × 组织延迟
         （市场说降5%销量+8%，但组织延迟2小时、执行偏差2% → 实际+6%）
```

## 七、健康指标

| 指标 | 健康标准 |
|---|---|
| 决策延迟 | 补货 < 2 小时，调价 < 30 分钟 |
| 执行偏差 | 平均偏差 < 10% |
| 审批通过率 | 合理（过高=AI 无效，过低=人不信任 AI） |
| 组织瓶颈 | 无单环节延迟占比 > 50% |

## 八、一句话总结

**组织模型是数字孪生的"粘合层"——前三层假设"决策立即无损执行"，组织模型补上"延迟和损耗"这一不现实假设；它把 600 人组织建模为决策流转网络（延迟 + 偏差 + 指令衰减 + 瓶颈），数据来自决策日志（AI 建议 vs 实际执行），LLM 的价值在于蒸馏人的"驳回理由"和"执行调整"这些隐性知识。没有组织模型，数字孪生是不完整的——因为再准的市场预测，经过一个慢、损、偏的组织，都会走样。**
