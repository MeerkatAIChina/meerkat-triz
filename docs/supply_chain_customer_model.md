# 数字孪生 · 供应链模型 & 顾客模型构建指南

> Meerkat-DT 四层模型中的两个：供应链模型（补货/库存决策）和顾客模型（用户长期价值，最难点）。与市场模型同层级，回答"决策动作 → 系统反应"。

# 第一部分：供应链模型

## 一、目标与边界

**核心目标**：预测"补货/库存决策 → 库存变化 → 缺货或积压"。

| 决策 X | 要预测的 Y |
|---|---|
| 补货 X 件 | 何时到货、库存曲线、会不会缺货 |
| 调整安全库存 | 缺货概率、库存成本 |
| 供应商选择 | 交期、成本、缺货风险 |

**边界**：供应链模型不预测"供应商倒闭"等极端事件，只预测"我的补货决策 → 库存状态"。

## 二、库存动态模型（基础）

库存变化遵循简单等式：

```
今日库存 = 昨日库存 + 今日到货 - 今日销量
```

数字孪生用这个等式**逐日推演**未来库存曲线：

```python
def simulate_inventory(initial_stock, daily_sales, lead_time, reorder_qty, days=30):
    """模拟未来 N 天库存变化。"""
    stock = initial_stock
    inventory_curve = []
    for d in range(days):
        stock -= daily_sales[d]      # 减销量
        if d == lead_time:            # 补货到货
            stock += reorder_qty
        inventory_curve.append(max(stock, 0))
        if stock < 0:                 # 缺货
            inventory_curve.append(("缺货", d))
            break
    return inventory_curve
```

**关键**：这是数字孪生"模拟"的核心——任何补货决策，先在孪生里推演库存曲线，看会不会缺货/积压。

## 三、补货决策的三参数模型

补货决策本质是定三个参数，每个都有标准公式：

### 1. 安全库存（应对需求波动）

```
安全库存 = z × σ_demand × √lead_time

z：服务水平系数（95% 服务 → z=1.65；99% → z=2.33）
σ_demand：日均销量的标准差
lead_time：补货周期（天）
```

**含义**：需求波动越大、补货周期越长，安全库存越高。

### 2. 补货点（ROP，什么时候补）

```
补货点 ROP = 日均销量 × 补货周期 + 安全库存
```

库存降到 ROP 就触发补货。

### 3. 经济订货量（EOQ，补多少）

```
EOQ = √(2 × D × S / H)

D：年需求量
S：单次订货成本（固定）
H：单位持有成本（年）
```

**含义**：订货成本和持有成本之间的平衡——订太少频繁订货（成本高），订太多持有积压（成本高）。

## 四、缺货成本 vs 积压成本（核心权衡）

供应链模型的核心矛盾（这正是 TRIZ 物理矛盾）：

```
库存多 → 不缺货但积压（持有成本高）
库存少 → 不积压但缺货（缺货损失高）
```

数字孪生的价值：**在模拟里找到"总成本最低"的库存点**：

```
总成本 = 持有成本 + 缺货成本 + 订货成本
持有成本 = 平均库存 × 单位持有成本
缺货成本 = 缺货次数 × 单次缺货损失（GMV 损失 + 用户流失）
```

## 五、数据需求

| 数据 | 粒度 | 最少历史 |
|---|---|---|
| 库存（当前 + 历史） | 天级 | 90 天 |
| 销量（日均 + 波动） | 天级 | 90 天 |
| 补货周期/供应商交期 | — | — |
| 订货成本、持有成本 | — | — |
| 缺货历史（何时缺过货） | 天级 | 90 天 |

## 六、LLM 的角色（供应链场景）

LLM 补充统计模型看不到的**软信息**：

| LLM 判断 | 作用 |
|---|---|
| 供应商产能/节假日 | 补货周期可能延长 → 调大 lead_time |
| 大促前备货 | 需求波动可能放大 → 调大 σ_demand |
| 供应商关系 | 交期承诺可信度 → 交期加缓冲 |

**纪律**：LLM 判断作为"参数调整因子"（如 lead_time × 1.2），不直接输出补货数字。

## 七、健康指标

| 指标 | 健康标准 |
|---|---|
| 缺货率 | < 2%（关键） |
| 库存周转率 | 品类健康值（如 12-24 次/年） |
| 库存持有成本 | 占总成本比例合理 |

# 第二部分：顾客模型（最难点）

## 一、目标与边界

**核心目标**：预测"运营动作 → 用户长期行为变化"（复购、流失、终身价值）。

**为什么最难**：用户行为延迟长（复购周期天到月）、归因难（用户买是因为我的动作还是自然行为）、且用户会"流失"（不可逆）。

## 二、RFM 分层（用户价值的入口）

先用 RFM 把用户分成 8 类，这是所有顾客模型的起点：

```
R（Recency 最近购买）、F（Frequency 频次）、M（Monetary 金额）
每个维度分高/低 → 2³ = 8 类用户
```

| RFM 组合 | 用户类型 | 运营动作 |
|---|---|---|
| 高高高 | 核心价值用户 | 维护、会员权益 |
| 低高高 | 重要流失风险 | 召回（高优先级） |
| 高低高 | 新晋高价值 | 培育、引导复购 |
| 低低低 | 沉默用户 | 低成本唤醒或放弃 |

## 三、留存模型（复购/流失的数学）

### 3.1 留存曲线

用户留存率随时间衰减，典型拟合：

```
留存率 R(t) = R₀ × t^(-α)   （幂律衰减）

R(t)：第 t 天的留存率
R₀：初始留存率
α：衰减系数（越大流失越快）
```

**拟合方法**：用历史用户的"首次购买后各天是否复购"数据，拟合出 α。

### 3.2 复购周期

```
复购周期 = 两次购买之间的平均时间
不同品类差异大：日用品 7-15 天，家电 6-12 个月
```

## 四、LTV 模型（终身价值）

```
LTV = 平均客单价 × 期望复购次数 × 毛利率

期望复购次数 = 留存曲线下的面积
```

**简化版**：

```
LTV ≈ 客单价 × 毛利率 × (1 / 流失率)

流失率 = 1 - 留存率（周期）
```

**关键用途**：LTV 决定了"获客成本 CAC 的上限"——如果 LTV < CAC，获客就是亏的。

## 五、流失预测模型（最有价值的预测）

预测"谁会流失"，这是顾客模型里**最能直接驱动决策**的。

### 5.1 特征

| 特征 | 含义 |
|---|---|
| 最近购买距今（R） | 越久越可能流失 |
| 复购频次（F） | 越低越可能流失 |
| 最近互动（浏览/加购/咨询） | 无互动 → 高流失风险 |
| 客单价趋势 | 下降 → 流失信号 |
| 负面事件（退货/投诉） | 触发流失 |

### 5.2 建模

用逻辑回归或简单规则：

```
流失概率 = sigmoid(β₀ + β₁·R + β₂·F + β₃·互动 + β₄·客单趋势 + β₅·负面事件)
```

**简化落地**：先用 RFM 规则（如"90 天未购买 = 流失风险"），积累数据后再上 ML。

## 六、顾客模型的难点（诚实指出）

| 难点 | 解法 |
|---|---|
| 归因难 | 用 A/B 测试隔离"我的动作"的影响 |
| 周期长 | 分短周期（复购，天级）和长周期（LTV，月级）分别建 |
| 数据稀疏 | 新品/新用户无历史，用同类用户类比 |
| 流失不可逆 | 重点是"预测流失"而非"挽回流失" |

## 七、LLM 的角色（顾客场景）

顾客模型里 LLM 的价值最大，因为用户行为有大量**文本信号**：

| LLM 分析 | 作用 |
|---|---|
| 评价/咨询文本 | 识别不满信号（流失前兆） |
| 用户画像 | 判断"为什么流失"（价格？质量？体验？） |
| 召回文案 | 生成个性化召回内容 |

**这是 LLM 比统计模型强的地方**——统计模型看到"用户 90 天没来"，LLM 能从评价里读出"用户抱怨质量"。

## 八、健康指标

| 指标 | 健康标准 |
|---|---|
| 复购率 | 品类健康值（日用品 >50%，家电 20-30%） |
| 流失预测准确率 | AUC > 0.7 |
| LTV/CAC 比 | > 3（健康） |

# 三、两模型与数字孪生的关系

```
市场模型：预测"动作 → 销量/GMV"
供应链模型：预测"销量 → 库存/缺货"（承接市场模型的销量预测）
顾客模型：预测"动作 → 用户长期价值"（跨越多个决策周期）
```

**三模型串联**：

```
调价决策 → 市场模型预测销量变化 → 供应链模型预测库存变化
         → 顾客模型预测用户长期价值变化
              ↓
         综合推演"这个决策的完整影响"
```

## 一句话总结

**供应链模型的本质是"库存的推演"（三参数：安全库存/补货点/EOQ，用总成本最低找平衡点）；顾客模型的本质是"用户生命的推演"（RFM 分层 → 留存曲线 → LTV → 流失预测），是四层模型里最难的（延迟长、归因难、流失不可逆），但 LLM 的价值也最大（能从评价/咨询文本读出流失前兆）。**
