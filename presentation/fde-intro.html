01 · 为什么做

TRIZ：把创新从"灵光一现"变成"可查的方法"

TRIZ（发明问题解决理论）由根里奇·阿奇舒勒自 1946 年起，从数十万件专利的分析中提炼。核心洞察：创新不是随机的天才灵光——同样的技术矛盾在不同行业反复出现，解法遵循可复用的模式。

结构化工具体系

  • 40 个发明原理 + 矛盾矩阵——解决技术矛盾（改善一个参数而不恶化另一个）
  • 分离原理——处理物理矛盾
  • ARIZ——重构与求解难题的完整算法
  • 技术系统进化法则——路线图思考

产业现状：分发方式极原始

三星、西门子、GE、波音曾用 TRIZ 内训数以千计的工程师；在中国，TRIZ 是国家创新方法推广工作的组成部分。

一家企业的 TRIZ 能力 ≈ 它养得起几个持证专家。方法论几乎只存在于昂贵的培训课程与咨询师身上。

01 · 为什么做

为什么是微调，而不是提示词工程

此前的 LLM+TRIZ 工作全部是提示词工程。微调能买到三样提示词买不到的东西：

术语纪律

原理编号引用、分析步骤完整性，固化进权重，而不是在 prompt 里恳求。每次调用都稳定交付，不随 prompt 漂移。

行为风格

直接可执行的回答，而非冗长思考流：基座中位 3,242 字符的 think 式作答，被压缩到 0.4× 篇幅（1,344 字符）且关键词覆盖持平。

能力内嵌

"查书答题"与"学会方法"的区别——在案例生成等生成类任务上最明显：模型输出的是方法论的应用，而非检索结果的复述。

商业本质：微调模型把方法论的应用能力，从按人天计费的咨询服务，变成边际成本为零的基础设施。企业创新的瓶颈往往不是点子，而是问题表述——大多数工程团队在创意阶段之前就卡住了：说不清自己真正面对的矛盾是什么。常驻模型恰好在这个断点上起作用。

11,096

0

04 · 怎么评

评测 harness：双轨评分，四条机检纪律

两条永不混合加权的轨

  • 关键词轨：逐题期望术语命中率（子串 + 人工别名表；报告别名表更新前/后双分数；漏判审计队列监控别名表本身）
  • judge 轨：LLM 评委四维 rubric 打 0–4 分（钉版 + T=0 硬断言）；臂 A 反冗长不截断，臂 B 同长度桶配对

统计协议

  • 全部对比逐题配对：bootstrap 10,000 次（stdlib Random(42)，指纹自检）95% CI
  • pass 率 Wilson CI + McNemar 精确检验；n<30 子集标"描述性"
  • pairwise 强制 AB/BA 双序；位置不一致率 >10% 自动作废单序

四条纪律，全部由代码强制

① 锚点谱系base 锚点 tag 非 base_goldfix 谱系 → exit 2 一票否决；双锚点 |Δkw|>0.2 题数 >10% → 冻结报警
② E0 铁律每题生成前冒烟断言空 think 块保留；剥离即污染（§故障 1 的根源）
③ 生成质量门think 残留/非空/中文占比/长度/英文草稿五道门 + 一次兜底重生成；持续 invalid 冻结评测而非静默混入
④ 拒答监控拒答模板命中率 >2% 不过门（v5a 实测 0/300）

确定性：贪心生成、T=0 评委（同族直连实测翻转率 0.000）、每份结果内嵌配置快照——同环境重跑逐位相同。

04 · 怎么评 · 本项目最有普适价值的部分

五类测量学故障——每一类都足以反转或作废结论

故障事实代价 / 沉淀的门规
1. 基线污染harness 剥离了 thinking-native 基座必需的空 think 块 → 基座 91/100 题输出未闭合英文思考草稿，两条轨评的都是草稿连续三个版本的 "+1.00 提升" 修复后反号为 −0.30；E0 铁律入代码
2. 评委位置偏差pairwise 评委位置不一致率 0.87：放第二位的候选赢 81%；文献摆动约 25pp，我们实测 62pp任何单序 pairwise 结论都是噪声 → AB/BA 双序合并成为唯一有效口径
3. 双轨系统性分歧关键词轨与 judge 轨仅共享约 10% 方差（Spearman r≈0.32）；v3 两轨显著反向；ARIZ 覆盖漏判率 31.7%门规：发布门必须双轨，任何单轨结论不得独立下判
4. 同族评委膨胀评委与数据生成器同族（Moonshot）；异源终审（Claude/GPT/Gemini 逐字复刻协议）方向确认但量级仅约 1/4同族 +0.39 中约 3/4 是评委家族效应；外部面板进决策门
5. 长度混淆base 篇幅 2.4×，rubric 惩罚冗长；等长对照下同族差值归零（−0.07 ns），而 base 仅靠压长指令自身 +0.46门规 D5：judge 显著结论必须附等长对照；D6：非确定评委结论附复跑噪声合成 CI
对 FDE 的意义：客户拿任何"微调提升 X 分"的宣称来问，我们有一套经过实战检验的审查清单——先查 prompt 渲染，再查评委构成，再查长度分布，最后才谈数字。

外部评委互相 Spearman 0.63–0.75，与 moonshot 仅 0.27–0.31——这是评分体系差异，不是噪声。显著结论均已过复跑噪声合成 CI（门规 D6）。

等长对照揭示的机制

让 base 按发布模型的逐题长度目标重答 300 题（实际超写 1.29×，如实报告）：

  • 同族差值 完全消失（−0.07 ns）——同族头条基本全是长度伪影
  • base 仅靠"写短"指令自身 +0.46——反冗长 rubric 一直在尽职
  • 外部评委反而给压短的 base 降分——它们奖励展开阐述，base 的长篇本身在买分
  • 等长下微调的关键词覆盖显著高于 base（+0.023）：base 被迫写短时丢覆盖，微调模型不会
现行发布口径：等长预算下经外部验证的质量优势（2/3 外部评委 +0.19/+0.27），以 0.4× 自然篇幅交付，并保住 base 被迫写短时保不住的关键词覆盖。

05 · 评得怎样 · 一句话定价

微调到底带来了什么

0.4×
回答篇幅：中位 1,344 vs 3,242 字符
think 式长作答 → 直接可执行作答
+0.19 / +0.27
等长预算下的 judge 增益
2/3 外部评委统计显著（复跑噪声合成 CI 后仍成立）

机制理解

  • 行为压缩是主线：微调把"先想后答"的冗长推理流，压成结构化直接作答——这对企业场景（API 计费、时延、可读性）本身就是价值，与质量增益相互独立。
  • 外部评委与外部评委才是仪器：同族读数 +0.39 被证明是"长度伪影 + 家族效应"的复合物；外部等长面板（+0.19/+0.27 显著）才把真实内容增益隔离出来。
  • 最强共识是定向修复的 concept_explanation：v4.1 再平衡修复的子集，在三个外部评委下全部显著（+0.24/+0.31/+0.29）——证明"测量 → 定向数据 → 门验收"的迭代闭环真实有效。
  • 被否决的 v5b 也已回溯溶解：其全部表观增益/损失经等长对照证明同为长度表面效应——行为改变是真的，对 base 的可测效果全是长度现象。

客户自有 GPU：HF 拉取基座 + 169MB LoRA，peft 热挂；或打包 vLLM 容器镜像交付。

# 路径②：OpenAI 兼容调用（DGX Spark 实例）
import openai
client = openai.OpenAI(base_url="http://<dgx-spark>:8000/v1", api_key="local")
resp = client.chat.completions.create(
    model="Meerkat-TRIZ-v1",
    messages=[{"role": "user",
               "content": "我们的锂电池想提升能量密度，但安全测试通不过，该用哪些发明原理？"}],
    temperature=0.6, top_p=0.95, max_tokens=4096)   # ⚠️ max_tokens 别低于 4096

# 路径③：客户侧 peft 热挂（HF 公开权重）
from peft import PeftModel
model = PeftModel.from_pretrained(base, "Meerkat-AI/Meerkat-TRIZ-v1")
# ⚠️ 必须保留 prompt 模板中的空 think 块——模型在该格式下训练，剥离会可测量地损害质量
两条红线（写进 model card，也是 FDE 话术）：① 保留空 think 块（E0 铁律，剥离 = 可测量的质量损害）；② max_tokens ≥ 4096（思维链长，额度不够会拿到空 content）。这两条犯了，客户会以为模型坏了——其实是用法错了。

07 · 怎么用 · 企业视角（融合企业讲解页）

对客户讲：不是更大的模型，而是受过 TRIZ 训练的创新工程助手

通用大模型

知识面广，能聊很多话题；但每次都要靠提示词告诉它"请扮演 TRIZ 专家"——换一个用户、换一个问题，输出就漂移。

Meerkat-TRIZ-v1

把 TRIZ 的术语、分析步骤和推荐方式训练进权重。不是临时扮演，而是受过系统训练——输出一致性不依赖提示词手艺。

专业化 · 不靠提示词"装懂"

术语纪律、分析步骤、原理推荐方式固化进模型；换问题、换用户，输出仍一致。

效率 · 更短但不靠省略

3,242 字 → 1,344 字：工程师读起来更快，API 成本更低；关键是 base 被迫写短时丢覆盖，v1 保得住。

可信评测 · 不"自己说自己好"

同族 +0.39 不作为质量证据（等长后基本消失）；正式口径用外部评委等长验证：Claude/GPT 显著为正。好看的说法让位于可辩护的说法。

客观指标 · 不只会"说好听话"

关键词轨不调用 LLM 评委，只检查 TRIZ 术语是否出现：v1 与基座同为 0.638，高于擂台中的 GPT/Claude/Gemini 参赛模型——窄领域专业化训练真实有效。

07 · 怎么用 · 企业视角

按角色：同一模型，九类企业用户的不同价值

CEO / 总经理

"AI 概念还是创新能力？"

把依赖少数专家的 TRIZ 方法变成员工随时可调用的基础设施；专家时间从重复讲解转向判断决策。

CTO / 技术负责人

"能接入现有系统吗？成本高吗？"

169MB LoRA，不重训 35B；挂在现有模型服务上，以较低成本获得可内部化的领域助手。

研发总监 / 总工程师

"真能帮工程师解决问题吗？"

问题澄清、矛盾分析、原理推荐、方案草稿、ARIZ 引导——不做最终设计，但让团队更快进入有结构的讨论。

创新负责人

"已有创新流程，加什么价值？"

把头脑风暴变成围绕矛盾、资源、发明原理的方法论驱动方案生成。

知识产权 / 专利团队

"能帮专利布局吗？"

从矛盾、替代原理、系统进化角度扩展思路，辅助交底书初稿与规避设计讨论。边界：不是专利检索系统，不替代律师意见。

产品经理

"我不懂 TRIZ，能帮我什么？"

把"要更轻但不能牺牲强度"这类模糊诉求整理成可讨论的技术矛盾——产品语言转工程语言。

工艺 / 制造 / 质量工程师

"现场问题能用吗？"

密封与散热、轻量化与强度、成本与可靠性、效率与噪音——TRIZ 擅长的权衡问题，帮现场经验进入结构化改进。

HR / 培训负责人

"能降低培训成本吗？"

TRIZ 入门教练：解释概念、生成练习、批改答案、提供案例——培训不必每次都从外部顾问开始。

咨询顾问 / 专家委员会

"会替代专家吗？"

不会。它是专家的初级助理：结构化初稿、扩展候选方向、检查术语步骤；判断、取舍、背书仍归专家。

07 · 怎么用 · 企业视角

企业工作流、对外话术与边界

① 把问题说清楚
"电池包要更轻，但强度不能降" → 改善参数、恶化参数、技术矛盾
② 生成解决方向
从分割、嵌套、预先作用、动态化、复合材料等原理中找候选路径
③ 形成评审材料
问题定义、矛盾分析、候选原理、方案草案、风险与验证建议
④ 专家做判断
专家不再从空白页开始，经验用在取舍与背书上

对外介绍时可直接用的三句话

给管理层：把 TRIZ 从少数专家手里的方法论，变成可规模化部署的 AI 基础设施；显著提高工程师进入结构化创新讨论的速度。

给技术团队：面向 TRIZ 微调的 35B LoRA；300 题金标上以 0.4× 篇幅交付，等长对照下获 2/3 外部评委显著质量确认。

给工程团队：把它当随时在线的 TRIZ 助教：定义矛盾、推荐原理、生成草稿；最终判断仍由工程师和专家完成。

对外始终说清楚的边界

  • 目前主要面向中文 TRIZ 问答与创新分析
  • 不是通用大模型的全面替代品
  • 不是专利检索系统，不替代律师意见
  • 不替代实验、仿真、安全验证与专家评审
  • 优势宣称限定在公开评测口径内，不外推成"全面超过所有大模型"

这些边界不是削弱说服力，而是让企业客户敢相信。最准确的定位：把一个高价值、低供给的专业方法域，做成可部署、可测量、可复现的模型能力。

总结

三句话带走

① 我们交付的不是"一个微调模型"，而是模型 + 基准 + 评测纪律三件套——后者才是面对客户技术质询时最硬的资产。

② 经外部验证的诚实口径：等长预算下质量显著更好（2/3 外部评委），以 0.4× 篇幅交付，关键词覆盖更稳；旧口径与最强基线打平——这句话同样写在 model card 里。

③ 落地路径已通：DGX Spark 生产栈在跑，OpenAI 兼容 API + 审批制 WebUI + 周回流管线；FDE 只需记住两条红线——保留空 think 块、max_tokens ≥ 4096。
