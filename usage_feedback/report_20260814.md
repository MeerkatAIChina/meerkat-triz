# Meerkat-TRIZ 使用数据周回流 — 目的与运行情况统计

---

## 一、管线目的

`usage_feedback` 管线的核心目标是将部署在 **DGX Spark (spark-855a)** 上的 **Meerkat-TRIZ-v1** 真实使用数据周期性回流，转化为 **v5c 训练候选料**。

### 关键设计原则

| 原则 | 说明 |
|------|------|
| **三道筛** | 原始日志 → 去重 → Moonshot 评委 Rubric 打分 → 人工抽审，**不直接进训练** |
| **双维度门槛** | SFT 候选需同时满足 `triz_correctness ≥ 4` **且** `data_value ≥ 4` |
| **失败归因** | 四类本地启发式标记失败案例：`identity_denial` / `repetition_loop` / `runaway_generation` / `empty` |
| **偏好对预留** | Open WebUI 的 👍/👎 feedback 表生成 `candidate_prefs.jsonl`，供未来 DPO 启用 |
| **密钥不落盘** | `MOONSHOT_API_KEY` 运行时通过 SSH 从 spark 读取，不写入仓库 |

### 自动化节奏

- 每周日 09:17 (Asia/Shanghai) 自动执行采集 + 分诊
- 人工动作：审阅 `triage/<date>/summary.md`，将认可的候选料归档进 v5c 数据池

### 已知四类 vs 新型模式

**未出现新型失败模式**。全部失败均落在已知四类之内：

- `identity_denial` ✓
- `repetition_loop` ✓
- `runaway_generation` ✓
- `empty` ✗（历史 4 期均未出现空输出）

### 归因猜想

1. **`runaway_generation` 高频**：`open-webui:14dbd2a0-d72` 这条"TRIZ中物理矛盾和技术矛盾的区别是什么？**一句话回答**"的会话在 4 期中反复出现，说明：
   - 增量采集可能未正确跳过已处理会话，或该会话被多次引用；
   - 模型对"一句话回答"的约束遵循性差，存在过度生成倾向。

2. **`identity_denial` 消失**：仅在 08-01 两期出现，后续未再出现，说明此类非 TRIZ 闲聊可能已被增量水位线跳过，或用户提问模式改变。

3. **`repetition_loop`**：仅在 `pi` 会话中出现，可能与 `pi` agent 的长对话循环机制有关。
