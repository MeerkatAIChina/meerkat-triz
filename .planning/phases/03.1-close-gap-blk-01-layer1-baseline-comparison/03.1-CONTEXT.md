**Gathered:** 2026-06-30

<domain>
## Phase Boundary

This phase closes audit gap BLK-01: Notebook 05 must load the actual Layer 1 (lm-eval-harness) benchmark scores from the baseline artifact so the before/after comparison report computes meaningful Layer 1 deltas.

What this phase delivers:
1. Updated baseline registration in Notebook 03 that records both the path to the raw lm-eval JSON and a small summary snapshot.
2. Updated Notebook 05 loading logic that reads Layer 1 scores from the lm-eval JSON file (not from `baseline['metadata']`).
3. Extended `aggregate_results()` in `utils/benchmark_utils.py` that accepts `layer1_general` inside `before_results` / `after_results` and computes per-task deltas.
4. Full Layer 1 suite re-run on the adapter in Notebook 05 so the adapter has its own Layer 1 scores for true before/after comparison.
5. A fallback quick baseline when `pipeline_state` has no usable baseline artifact.

Scope does NOT include: changing how Layer 2 TRIZ or Layer 3 performance benchmarks are produced, adding new benchmark tasks, UI/report styling beyond delta tables, deployment.

**Override note:** This phase overrides Phase 3 D-01 for Layer 1 only. Phase 3 D-01 said Layer 1 general benchmarks are loaded from `pipeline_state` baseline registry and not re-run. For BLK-01, the adapter Layer 1 scores must be produced by re-running the Layer 1 suite on the adapter in Notebook 05.
</domain>

<decisions>
## Implementation Decisions

### Baseline artifact schema (D-01)
- Notebook 03 keeps `baseline_results.path` pointing at the aggregate benchmark report / `results/` directory.
- Notebook 03 adds a metadata field `layer1_path` that points to the actual `lm_eval_results_YYYYMMDD_HHMMSS.json` file produced by `run_lm_evaluation()`.
- Notebook 03 also stores a small pre-computed summary in metadata (`tasks`, per-task primary metric snapshot, `perf_throughput`) for quick display without re-parsing the full JSON.

### Adapter Layer 1 source (D-02)
- Notebook 05 re-runs the full Layer 1 suite (MMLU-Pro, GPQA, HumanEval, MATH, BBH as configured in `BENCHMARK_CONFIG`) on the adapter after Layer 2 TRIZ and Layer 3 performance benchmarks.
- This provides true before/after Layer 1 deltas and satisfies the Phase 3.1 success criterion that `aggregate_results(...)` receives valid `layer1_general` scores for both base and adapter runs.
- This decision overrides Phase 3 D-01 for Layer 1 only; Layer 2 and Layer 3 handling from Phase 3 remains unchanged.

### aggregate_results API shape (D-03)
- Extend `before_results` and `after_results` dictionaries to optionally include a `layer1_general` key whose value is the lm-eval results dictionary for that model run.
- In comparison mode (`before_results` and `after_results` provided), `aggregate_results()` reads `layer1_general` from each dict, computes per-task deltas using the existing `_compute_deltas()` helper, and stores the result under `report["layer1_general"]`.
- The existing `general_results` parameter remains for single-run / backward-compatible usage.
- Preserve existing test behavior in `tests/test_benchmark_utils.py`; new Layer 1 delta behavior must be additive and not break existing assertions.

### Missing-baseline fallback (D-04)
- If `pipeline_state` has no `baseline_results` artifact, or if `baseline_results.metadata.layer1_path` does not exist, Notebook 05 auto-runs a quick baseline on the base model.
- Quick baseline = one representative Layer 1 task plus Layer 3 performance, consistent with Phase 3 D-04.
- Print a warning: "Baseline Layer 1 file not found — running quick baseline now. Run Notebook 03 for full baseline."

### Claude's Discretion
- Exact JSON key used for the per-task metric inside the lm-eval `results` block (e.g., `acc`, `acc_norm`, `exact_match`) — use the same extraction logic as `print_evaluation_summary()`.
- Which single Layer 1 task to use for the quick baseline fallback (pick one from `BENCHMARK_CONFIG['general_benchmarks']`).
- Exact formatting and color-coding of the Layer 1 delta table in Notebook 05.
- Error handling when individual lm-eval tasks fail (skip and record `null`, or fail the cell).
- Whether to cache adapter Layer 1 results to a JSON file in `results/` so a second run of Notebook 05 can reuse them.
</decisions>

<specifics>
## Specific Ideas

- Notebook 03 currently registers `baseline_results` with `path` set to the latest aggregate report file and metadata containing only `tasks`, `perf_throughput`, and a TRIZ summary. It does not store the actual lm-eval JSON path.
- Notebook 05 currently loads `general_results = baseline.get('metadata', {})`, which is the summary metadata, not the full Layer 1 scores.
- `aggregate_results()` currently stores Layer 1 under `report["layer1_general"]` with `source: "pipeline_state"` and `metrics: general_results`, but it does not compute deltas and does not look for `layer1_general` inside `before_results` / `after_results`.
- Notebook 05's `display_delta_table()` expects metrics with `before`, `after`, `delta`, `delta_pct` keys — the same structure `_compute_deltas()` already produces.
- The current `aggregate_results()` tests in `tests/test_benchmark_utils.py` cover missing throughput and performance-score computation; any Layer 1 delta additions must not change those outputs.
</specifics>
