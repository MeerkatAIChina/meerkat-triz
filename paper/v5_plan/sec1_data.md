## 1. 行为风格目标的确定(Owner 裁决前置项)

### 决策

v5 数据方案的风格目标**不由本方案自定,必须先由 Owner 裁决**,三选一:

- **A. 简洁直接**(维持 v2/v4 现状):completion 均长 ~300 字符、直接作答、无 think 块。
- **B. 详细 verbose**(向干净 base 看齐):completion 均长 ≥1500 字符、结构化详尽作答。
- **C. system-prompt 可控(推荐)**:同一批 instruction 配双风格 completion,训练 prompt 的 system 段携带风格指令,推理时由 system prompt 切换。

### 论证

【已证实】E0 干净锚点终局证明:**v1–v4 四轮微调学到的本质上是行为风格转换,不是能力提升**。具体证据链(`paper/experiments/e0/E0_report.md` §4.3、§4.5):

- v4−base judge 差 **−0.30 [−0.46,−0.14] 显著为负**;v2−base 同为 **−0.29 [−0.42,−0.16]**;kw 轨双双不显著(−0.0074 [−0.0497,+0.0345] / −0.0158 [−0.0550,+0.0236]);
- 微调模型的回答长度 ~300 字符 vs 干净 base 均值 3250 字符——**压缩到 ~1/10,关键词覆盖不丢**;
- assessment_report(`paper/assessment_report.md` §四)已把 v2 的发货定位说死:"行为风格转换器……若产品 KPI 是'绝对答案质量超过 base',四个版本均未达成;若 KPI 是'简洁直接的专业作答体验',v2 达标"。

【已证实】风格目标直接决定数据构造,而数据构造会写进模型行为——E2 已证明"质量门的排序规则(如'长答案优先')是训练信号"(`paper/assessment_report.md` 工程启示⑤)。v4 训练数据 concept 子集均长 277.4 字符(p50 264)(`paper/experiments/e2/e2_data_attr.json`),模型输出即 ~285 字符(`paper/stats_review.md` §4.3)——**completion 长度分布就是模型输出长度分布的先验**。

【推断】为什么推荐 C:

1. **E0 遗留的"长度混淆未解"问题(`paper/assessment_report.md` §七.5)只能靠双风格模型正面回答**:judge completeness 维度天然偏好长答,缺长度控制后的公平对比,"base 质量更高"与"judge 偏好冗长"两种解释目前无法分离。若 v5 是双风格模型,同一模型用两个 system prompt 各生成一次,即得**同模型、同权重、仅长度不同**的受控对比——这是 E0 §6 待办②("建议补一个长度控制后的公平对比")的最干净实现。
2. 单一风格是把鸡蛋放在一个 KPI 篮子里:A 赌"产品要简洁",B 赌"产品要 judge 高分"。C 把两种能力都留在模型里,产品侧与论文侧都不被锁死。
3. 成本可控:双风格只需为 ~40% 样本生成长答(见下),API 增量约等于重生成 ~2,500 条 completion,远小于一次 7h 训练 run 的机会成本。

**三种裁决对应的数据构造法**(具体参数):

| 裁决 | 构造法 | 具体参数 |
|---|---|---|
| A 简洁直接 | 沿用 v4 管线输出风格,加长度上限门 | completion ≤400 字符硬上限;超长样本截断至最近句号,截断后 <150 字符者丢弃 |
| B 详细 verbose | 以干净 base 回答为风格模板重写全部 completion | 用 `results/e0_basefix/` 的 100 条 base_goldfix 回答(均长 3250 字符、质量门:非空+中文字符占比 ≥0.3,见 `paper/experiments/e0/E0_report.md` §3)作 few-shot 风格示例;Moonshot API 重写,下限 1200 字符;p95 对齐 2048 token 训练上限 |
| **C 双风格(推荐)** | instruction 全量保留短答;**按子集分层抽 40% 生成对应长答**,与短答并存 | 短答:completion ≤400 字符,system 段加"简洁模式:直接给出结论与要点,不超过 300 字";长答:completion 1200–2500 字符,system 段加"详细模式:给出完整的结构化分析,包含术语定义、推理过程与实施建议";同一 instruction 的长短两版**必须同组同侧划分**(见 §7),训练样本数 = 短答 N + 长答 0.4N |

### 风险与缓解

- **风险 C-1**:双风格混入后模型学到"长度分布模糊",两种模式都不像。缓解:风格指令放在 system 段而非 user 段(v4 管线 prompt 由数据构建侧完整渲染,`pipeline_v4_remote/README.md` §completion-only loss 机制允许直接控制 prompt 文本);金标评测时按两个 system 变体各跑一遍,按风格分组报告,任一风格臂显著劣于 v2 单风格基线即触发归因。
- **风险 C-2**:长答样本的 Moonshot 重写质量参差,引入新噪声。缓解:长答生成走与 §3 相同的三规则清洗 + 10% 人工抽检队列(沿用 `v4_gold_review.md` 模式)。
- **风险 A/B**:若 Owner 选 A,接受"judg 轨 −0.29~-0.30 差距在 v5 大概率依旧存在"的预期,论文叙事维持"效率与风格"定位;若选 B,需重测 E0 全部锚点(长答模型 vs 长答 base 才是公平对),评测预算 ×1。

## 2. 真实锚定:385 条种子 3 倍上采样

### 决策

385 条种子数据**显式注入 v5 训练集,每条复制 3 份(×3 上采样)**,注入点在全部质量门之后、训练/验证/测试划分之前;种子与其一切改写衍生物按同一 group id 划分,永不跨侧。

### 论证

【已证实】v1–v4 的真实数据缺口有完整文件记录:

- corpus 路径下问答 **100% 由 Moonshot 生成**,"真实"仅体现在教材片段 grounding——"Moonshot 的表述风格就是模型的天花板"(`docs/training_retrospective_2026-07-20.md:61`);
- 02b 路径真实占比仅 6.1%,低于 20–30% 的理论目标;且 DATA-02 的偏差以"记录偏差+照常打勾"处理,从未补救(`docs/training_retrospective_2026-07-20.md` §2.3);
- v4 数据构建输入为 v2 语料 10,327 条 + ariz boost 674 条(`paper/evidence_table.md` ④),**385 条种子不在 v4 训练集中**——即种子至今从未真正锚定过任何一版已评测模型。

【文献支持】retrospective 同处引用外部实证:**等量真实数据微调一致优于合成(+11.9%,arXiv 2602.04482)**(`docs/training_retrospective_2026-07-20.md:61`);retrospective P1 改进清单第 1 条即"真实锚定:385 条种子 2–3 倍上采样进训练集"(`docs/training_retrospective_2026-07-20.md:129`)。

【推断】取区间上限 ×3 而非 ×2:按 §4 的 cap 调整,预计 v5 训练集 ~7,000–8,000 条,385×3=1,155 条等效样本占比 ~15%——恰好回到 DATA-02 最初 20–30% 目标的下沿附近(考虑 1,155 是"重复计数"而非独立样本,真实独立占比 385/7,500≈5%,×3 是使真实信号在 loss 中不被 95% 合成样本淹没的最低有效权重);超过 ×3 则小样本重复过拟合风险盖过锚定收益(无实证,保守取 retrospective 建议区间上限)。

### 风险与缓解

- **风险 2-1**:种子质量未经 TRIZ 专家审核,"种子由谁编写、是否经 TRIZ 专家审核:仓库无任何记录"(`docs/training_retrospective_2026-07-20.md:52`)——上采样会放大种子中的错误。缓解:种子先过 §3 的二次清洗三规则;Owner 裁决项——建议抽取 30 条种子送 TRIZ 顾问快审(半天成本),错误率 >10% 则该子集种子降权至 ×2。
- **风险 2-2**:种子与评测集泄漏。缓解:种子同样过 §7 的双重去污门(对金标 100 题 + eval2 扩充集 495 题,J≥0.5 剔除),命中者不入训练;种子衍生物同组划分(§7)。

## 3. 种子二次清洗:三条具体规则

### 决策

385 条种子在注入前执行三条清洗规则,全部命中计数写入 manifest(§8):

1. **同题不同答**:归一化 instruction 相同而 output 不同的冲突组,**整组丢弃**(不允许"投票保留多数答");
2. **公式化收尾**:output 末 80 字符与模板收尾黑名单(首条即"综合评估:……建议进一步进行专利检索和竞品分析")匹配者,**截去收尾句**;截断后 <150 字符则整条丢弃;单一收尾模板在清洗后种子中的残留率必须 =0;
3. **超短回答**:output <150 字符整条丢弃(覆盖 retrospective 记录的 26 条 <60 字符样本)。

### 论证

【已证实】三类缺陷均有文件级记录(`docs/training_retrospective_2026-07-20.md:51-52`):

- innovation_assessment 有 **10 组"同题不同答"**——"去重只认完全相同的样本,冲突监督信号会原样进入训练";
- 答案高度公式化,"多条以同一句'综合评估:……建议进一步进行专利检索和竞品分析'收尾";
- **26 条 output 不足 60 字符**。

【已证实】规则 1 的有效性已被 v4 管线实战验证:v4 门 2"同 instruction 多答案冲突组整组丢弃"在 11,001 条输入上丢弃 30 组/68 条(`paper/evidence_table.md` ①),是"旧管线同题不同答混入的修复"(`pipeline_v4_remote/README.md` §数据门 2)。冲突监督信号对 LoRA 小容量适配器(84.66M 可训练参数,`docs/training_retrospective_2026-07-20.md:75`)的伤害被 ×3 上采样进一步放大,因此 v5 对种子采用与 v4 相同的最严口径(整组弃,不做多数投票——10 组样本量不足以判定哪一答为真)。

【推断】规则 2 取"截句"而非"整条丢弃":公式化收尾的样本前文仍有监督价值,种子总量仅 385 条,丢不起;但残留模板句必须清零,因为 v1 已证明模板句会被模型学成热键收尾(复盘原文即指"答案高度公式化"是残留质量问题)。

### 风险与缓解

- **风险 3-1**:整组丢弃可能损失 innovation_assessment 子集 ~20 条种子(10 组),该子集种子变薄。缓解:该子集缺口用 §5 同步生成的同子集合规样本配额补足,保持 6 子集种子数均衡(原规划每子集约 100 条,`config.py:99-130`)。
- **风险 3-2**:收尾模板黑名单靠人工枚举,可能漏网。缓解:构建时统计所有样本末 80 字符的频次分布,频次 ≥3 的收尾串全部入黑名单(数据驱动,不只依赖复盘记录的一条)。

## 4. cap 门修复:弃用"长答案优先",改"术语覆盖优先+随机补足",cap 提至 2500

### 决策

v4 的子集再平衡门(concept_explanation / innovation_assessment 各 cap 1500、**cap 内优先保留 output 更长者**)在 v5 做两项变更:

1. **cap 值 1500 → 2500**(两子集同);
2. **门内选取规则弃用"长答案优先",改为两阶段**:先用 TRIZ 工具术语言表做**贪心最大覆盖选取**(保底配额 60%),剩余 40% 配额**分层随机**(按 output 长度分三桶均匀抽取,消除长度方向的选择偏差)。

术语言表 v1.0(从 E2 真缺失清单与现有 KEYWORD_MAP 构建,构建时落 manifest):功能分析、矛盾矩阵、S曲线、40个发明原理、技术矛盾、物理矛盾、理想解/IFR、资源分析、物场分析、因果链、Functionality、Cost、改善参数、恶化参数、通用工程参数。

### 论证

【已证实】"长答案优先"规则的两个实测后果(`paper/experiments/e2/e2_data_attr.json`):

- cap 门把 concept_explanation 从 3,527 砍到 1,500(丢 2,027 条)、innovation_assessment 从 3,311 砍到 1,500(丢 1,811 条),**两门共丢 3,838 条 = 输入的 34.9%**,v4 训练集因此只有 5,739 条;
- 保留集显著更长(Mann-Whitney U **p=5.3e-25**)但均长仅 277.4 vs 263.8 字符,**方向显著、效应量仅 +5%**(`paper/evidence_table.md` 引用;E2 报告同口径:"方向显著、效应量小")——即为 +5% 的长度漂移付出了 2,027 条 concept 样本的多样性。

【已证实】术语缺失与该门存在时间链与机制链:E2 终判 v4 真缺失 TRIZ 工具术语言名 **8 词次**(功能分析×3、Functionality、Cost、矛盾矩阵、S曲线等,synonym 伪影 0 条,`paper/experiments/e2/e2_report.json` → `kw_reclass.true_missing`);stats_review §4.3 明确"**不能排除'清洗误伤了术语多样性'**——建议下一轮在 CE 类训练样本中保留术语枚举式答案"(`paper/stats_review.md:156`);工程启示⑤:"数据质量门的排序规则是训练信号,会写进模型行为"(`paper/assessment_report.md` §三 E2)。

【推断】两点设计判断:

- cap 2500 的取值:concept/innovation 两子集 pre-cap 各 ~3,300–3,500 条,cap 2500 保留 ~71–75%,既继续履行"再平衡防单子集主导"的职能(两门后预计训练集 ~7,500 条,两子集合计占比 ~55% 降至合理区间),又把"丢弃率 34.9%"降到 ~20% 以下;若 §1 裁决为 B/C(长答注入),可进一步上调至 3000,由数据构建时的总量预算反推。
- "覆盖优先 60% + 随机 40%"的配比:覆盖配额保证 15 个术语言每词 ≥30 条样本(15×30=450 条 < 2500×60%=1500 配额,可行);保留 40% 纯随机是为避免"术语言表本身成为新的选择偏差"——v3 的教训正是定向优化一个维度会砸另一个维度(`paper/stats_review.md` §3.2:v3 堆关键词致 judge 轨 −0.0682 ✅)。

### 风险与缓解

- **风险 4-1**:术语覆盖优先把 concept 子集变成"术语复读机",重蹈 v3 堆关键词覆辙。缓解:两轨决策门把关(工程启示⑦,`paper/assessment_report.md` §三):v5 金标评测若出现 kw 升 judge 降的两轨反向,默认回滚并启动归因;术语言表只用于**选取**样本,不改写样本内容。
- **风险 4-2**:cap 提高后训练集变大,训练时长超"单 run 一天"预算。缓解:v4 实测 11.0 s/step、batch 8(`paper/evidence_table.md` ③),7,500 条 ×2 epochs ≈ 1,875 步 ≈ 5.7h,加评测仍在 1 天内;若超时,先砍 cap 至 2000 而非砍 epochs。

## 5. Safety-Refusal 子集补齐 300 条

### 决策

新增 safety_refusal 子集 **300 条**(推荐值,区间 200–400),分 5 类拒答场景各 60 条:

1. 超出 TRIZ/技术创新咨询范围的请求(如情感咨询、代码生成);
2. 危险工程操作建议(绕过安全规范的压力/电气/化学操作);
3. 诱导专利侵权或规避有效专利的请求;
4. 涉及医疗、安监、环保合规结论的请求(须拒答并建议咨询持证专业人士);
5. 索取客户保密信息的请求。

生成走 Moonshot API(与主语料同管线),全部样本过 §3 同标准清洗 + **10% 人工抽检**;拒答 completion 模板 ≤3 种,每种 ≤5% 占比防模板化。

### 论证

【已证实】缺口事实:技术方案规划 Safety-Refusal **400 条(7%)**,v1/v2 两轮数据均为零(`docs/training_retrospective_2026-07-20.md:58`);"面向客户交付/私有化部署场景,这是合规与品牌风险"。retrospective P1 第 1 条明确要求"补 Safety-Refusal 子集 200–400 条"(`docs/training_retrospective_2026-07-20.md:131`)。

【推断】取 300 条:按 v5 训练集 ~7,500 条计,300 条占比 4%,回到规划值 7% 的下沿之内、又留出 §1 长答注入后的占比余量;拒答类样本的监督信号简单(模式高度重复),边际收益递减快,400 条上限不必要。

### 风险与缓解

- **风险 5-1(过度拒答)**:拒答样本污染正常 TRIZ 问答,模型对合规问题也开始拒答。缓解:① 占比硬上限 5%;② v5 金标评测新增 overrefusal 检查——100 道金标题的回答不得出现拒答模板,出现率 >2% 即决策门不通过;③ general_probe 30 题继续作为通用回归门槛(该门 v1 曾显著退化 −0.133 ✅,`paper/evidence_table.md` ②-C)。
- **风险 5-2**:拒答模板被学成热键,损害 judge 轨。缓解:模板 ≤3 种且每条 completion 必须包含"拒答理由 + 可替代的合规帮助方向"两段结构,不允许单句拒答。

## 6. ariz 定向数据的继承:保留存量、不追加增量、占比封顶 15%

### 决策

v5 **继承** v3 ariz boost 的全部 594 条入训样本(674 − 80 评测预留,`paper/evidence_table.md` ④),**不追加第二轮 ariz 定向生成**;ariz_guidance 子集占训练集比例封顶 **15%**(超限则随机下采)。

### 论证

【已证实】得——ariz 定向数据在干净锚点下产出了全项目最稳健的正面发现:

- 金标 ariz 子集 v4 双轨四方最高:kw **0.7494** / judge **2.85**(`paper/evidence_table.md` ②-E;v4 训练数据 = v2 语料 + ariz boost);
- E3' rubric 轨 v4 vs 干净 base **+0.083 [0.033, 0.142] 显著**,v2 vs base +0.075 [−0.025,0.15] 不显著——v4 的 ARIZ 语义优势在干净锚点下依然显著(`paper/experiments/e3/e3_report.md` 末段;`paper/assessment_report.md` §三 E3);
- 关键词漏判率 31.7%(19/60)证实"v2 ARIZ 回退"大部为关键词伪影,ariz 子集的真实语义水平被 kw 轨系统性低估(`paper/experiments/e3/e3_report.md`)。

【已证实】代价——v3 时代两轨显著反向:eval2 中 v3 vs v2 关键词轨 **+0.0556 [0.0010,0.1099] ✅** 而 judge 轨 **−0.0682 [−0.1078,−0.0296] ✅**;机制归因"v3 学会了堆关键词,语义质量反降","仅 kw 过"高达 31 题(`paper/stats_review.md` §3.2;`paper/evidence_table.md` ②-C)。

【推断】为什么"保留存量但不追加":同一批 594 条 boost 样本在 v3 训练(计划 4 epochs、实际 1.249 epochs、ariz 数据占比更高)下产出堆关键词行为,在 v4 训练(质量门链 + completion-only loss + 1.393 epochs 早停)下产出双轨最高——**差异更可能来自训练配置与数据占比,而非 boost 样本本身有毒**。但存量复用不等于安全:v4 ariz 占比 831/5,739 = 14.5% 已接近上限,追加第二轮 boost 会同时推高占比与"v3 机制"复现概率,而 ariz 已是双轨最强的子集,**边际收益最小的方向不该再加重量**。E3 的 per_step 数据显示 v4 唯一弱项是 step6(0.3,`paper/experiments/e3/e3_report.md`)——若未来要补,方向是补"step6 方案评估/实施"覆盖的样本,而不是再加总量。

### 风险与缓解

- **风险 6-1**:15% 占比封顶触发下采,丢弃部分 boost 样本,ariz 优势回落。缓解:封顶触发时优先丢弃与 v2 语料 Jaccard 相似度高的 boost 样本(保留信息增量大的),并检查金标 ariz 子集 kw ≥0.70 是否保持(v4 为 0.7494)。
- **风险 6-2**:eval2 扩充集的 80 条 ariz 评测预留与训练用 594 条同批生成,同源评测可能高估 ariz 优势。缓解:v5 结论一律以金标 100 题(ariz n=20,独立 chunk 抽样)为准,eval2 扩充集仅作回归监测;两套评测体系不可互比的口径声明沿用(`paper/evidence_table.md` ⑤-9)。

## 7. 去污与防泄漏:双重去污 + 划分交叉检查

### 决策

v5 去污门升级为**双重参照**:

1. **参照集 A**:金标集 `v4_gold.jsonl` 100 题(沿用 v4 门 4);
2. **参照集 B**:eval2 扩充集 `sample_data_expanded.json` 465 条 + `general_probe.json` 30 题(新增——v4 未对该集做去污);
3. 规则:训练候选与任一参照集 question/instruction 做 token 3-gram Jaccard,**J ≥ 0.5 剔除**;J ∈ [0.4, 0.5) 进入人工审查队列(逐条判定);
4. 划分沿用 v4 的分层分组 85/10/5(seed=42),种子及其衍生物、同 instruction 的长短双风格版**同组同侧**;划分后 test/validation 与 train 再做 J ≥ 0.5 交叉检查,命中者移回 train(v4 移回过 52 条,`paper/evidence_table.md` ④);
5. 去污结果由**独立脚本复核**(不复用构建脚本的内嵌计数),复核数字写入 manifest。

### 论证

【已证实】v4 的去污门本身有效但覆盖不全:v4 门 4 对金标集 J≥0.5、0 命中,门 6 划分交叉检查移回 52 条(`pipeline_v4_remote/README.md` §数据;`paper/evidence_table.md` ①);但 **eval2 扩充集(465 条)与 general_probe(30 题)从未进入任何一版的去污参照**——v3 的 80 条 ariz 评测预留靠构建时一次性交叉去重(`build_v3_and_evalset.py:46-54`),v4 数据构建未对该集复查。同时 assessment 诚实声明第 7 条:"训练数据泄漏未独立检验:harness 有金标去污门(J≥0.5, 0 命中),但 W3 未独立复核"(`paper/assessment_report.md` §七.7)——v5 必须把"独立复核"从声明变成机制。

【推断】阈值维持 0.5 而非收紧到 0.4 直接剔除:0.4–0.5 区间在中文短问题上会误伤"同领域不同题"的合法样本(TRIZ 术语天然高重叠),人工队列比自动剔除的代价小(预计量级几十条);3-gram 对中文的敏感度假靠"token = 拉丁/数字连续段或单汉字"的既有实现缓解(v4 已在 11k 条上秒级完成,`pipeline_v4_remote/README.md` 门 3),不另引 embedding 去重以控制管线复杂度。

### 风险与缓解

- **风险 7-1**:eval2 扩充集的 reference 由训练目标文本自动抽取(stats_review §5.3 证据 2),与训练语料天然近缘,J≥0.5 剔除可能误杀一批合法样本、缩小训练集。缓解:命中计数按参照集分别报告;若 B 集剔除量 >3%,触发人工复核而非照单全收。
- **风险 7-2**:金标集未来扩充(如 E6 通用探针 30→120 题)后旧去污失效。缓解:manifest 记录参照集版本与 sha256,任何评测集变更后数据构建必须重跑去污门(v4 已有"金标完成后必须重跑"先例,`pipeline_v4_remote/README.md` 门 4)。

## 8. 数据 manifest 制度化

### 决策

v5 数据构建的强制产物为 `data/processed/v5_data/MANIFEST.md` + 构建报告 JSON,随训练 run 提交 git,包含(缺一即构建失败):

1. 全部输入文件清单 + sha256(v2 语料 checkpoint、ariz boost checkpoint、385 种子文件、safety 新增批);
2. 每道质量门的命中/丢弃计数(沿用 v4 `v4_data_report.json` 的 gates 结构,新增:种子清洗三规则、术语覆盖选取明细、双重去污分参照集计数);
3. 最终 train/validation/test 条数、子集分布、长度分布(mean/p50/p95)、风格配比(短/长);
4. 划分参数(seed=42、分组键、退化声明——v4 因语料无 source/chunk 标识降级为 instruction 前缀聚类,`paper/evidence_table.md` ⑤-11,v5 须如实继承或修复该字段);
5. 输出 jsonl 的 sha256 与行数;对应训练 run 的 config 文件名与 git commit。

### 论证

【已证实】无 manifest 的历史代价:"该数据集不在本仓库(仅在 DGX),无 manifest(条数/分布/生成参数/哈希),**无法复现'2,662 条到底是什么'**"(`docs/training_retrospective_2026-07-20.md:56`);"548 vs 385"的文档数字漂移残留于 4 处文件(`docs/training_retrospective_2026-07-20.md:50`);retrospective P1 明确要求"数据 manifest 制度化:每版训练集落 `data/MANIFEST.md`(条数/分布/参数/哈希/对应 run);02b/02d 改用时间戳目录禁止互相覆盖"(`docs/training_retrospective_2026-07-20.md:132`)。v4 的 `v4_data_report.json` 已是可用雏形(输入/门/划分/终态俱全,`paper/evidence_table.md` ①④),v5 在此基础上**增加种子链与双风格两个新维度**并补 git 入库环节(v4 报告同样仅存远端)。

### 风险与缓解

- **风险 8-1**:manifest 手写滞后于实际构建,重演"文档系统性滞后于代码"。缓解:manifest 由构建脚本自动生成,人工只填决策备注;里程碑关闭加"文档新鲜度"硬门槛(retrospective P1 工程侧第 4 条)。
- **风险 8-2**:远端单点——"全部训练产物与评测结果仅存 DGX,故障即丢失"(`docs/training_retrospective_2026-07-20.md:98`)。缓解:构建完成即 `git commit + push`(或 SHA-256 双向同步回本地仓库),manifest 入库是训练启动的前置条件。
