## 1. 执行摘要(一页)

**为什么要重训**:E0 干净锚点终判证明,v1–v4 四轮微调的"增益"大半是测量伪影——旧决策门在 base 草稿污染下判出 v4−base judge **+1.00 [0.80,1.19]**,干净锚点下反号为 **−0.30 [−0.46,−0.14]**(`paper/experiments/e0/E0_report.md` §4.3)。真实画像是:v4≈v2(judge −0.01 [−0.13,+0.11]、kw +0.008 不显著),微调学到的是**行为风格转换**(回答 3250 → ~300 字符、kw 覆盖持平),且付出两处实代价:concept_explanation kw 真退化 −0.083 [−0.149,−0.023](E2 终判真缺失 8 词次)与 judge 轨 −0.30(含未分离的长度混淆)。v4 的质量门链与 completion-only loss 是对的,但数据配比、超参排程、评测协议三处存在可修复缺陷。

**v5 与 v1–v4 的本质区别**:v1–v4 是"改训练、用旧门验收";v5 是"**先修测量,再改数据,超参小扫终裁**"——决策门 2.0 先锁定干净锚点、双臂 judge(长度归一化 + 同长度桶)、双轨裁决规则,再让训练结果接受审判。v5 的目标**不是整体超越 base**,而是四点:① 保持关键词持平与 ARIZ 语义优势(E3' +0.083 [0.033,0.142] 显著);② 修复 concept 术语退化;③ 长度控制后的 judge 公平对比(差值 CI 下限 > −0.15);④ 通用能力不回退(探针 120 题,> −5pp)。

**预期收益与成本**:核心线 ≈ **15.6 GPU·h**(P0 小扫 6.6h + 冒烟 1h + 主 run ≤7h + 评测 1h)+ API ~6h + 人工 ~4h,分三日执行;全条件消融触发上限 38 GPU·h。收益:v5 或成为首个"在干净锚点 + 长度控制下证明自己"的版本,或为"简洁风格定位"提供最终诚实证据——两种结局都是论文级结论。

**最大风险**:风格目标未裁决(P0 阻塞项)——数据构造法、训练样本数、评测预算全部悬于该项;其次为长度混淆在双臂 judge 下仍不可分(风险登记册 R-01)。

### 2.2 为什么重训是合理的

1. **微调的真实效果是风格转换,而风格转换本身是可辩护的产品价值**——`assessment_report.md` §四已定位:"若 KPI 是'简洁直接的专业作答体验',v2 达标"。v5 的任务是把这一定位从"叙事"升级为"在公平测量下被证明的事实"。
2. **两处实代价均有明确修复路径且修复成本远低于一次训练 run**:concept 术语退化的机制链已定位到 cap 门"长答案优先"(E2 + stats_review §4.3);judge −0.30 的测量条件缺陷(截断不对称 + 无长度控制)由双臂 judge 正面回答(E0 §6 待办②)。
3. **已验证的资产全部保留**:v4 七门数据链、completion-only loss、best-checkpoint 制度、干净锚点协议——v5 站在修复后的管线上做增量,不是推倒重来。
4. **诚实边界**:v5 不以"整体超越 base"为验收目标。该目标在现有证据下既不必要(风格定位成立)也不可达(judge 轨 MDE 与长度混淆的现实)。决策门 2.0 的 G1 阈值 −0.15 即"把差距压缩一半以上"的最小实质进展声明。

## 4. 数据方案(支柱一合并)

> 基座:v4 干净管线(`pipeline_v4_remote/README.md` 七门链)。v5 做 8 项变更,逐项"决策—论证—风险"如下,重复背景已删,四段式论证保留。

### 4.1 风格目标:Owner 裁决前置项(P0 阻塞)

**决策**:三选一,**推荐 C(system-prompt 可控双风格,短答:长答 = 6:4)**;否决则退 A(简洁直接)。

- **A 简洁直接**:completion ≤400 字符硬上限;超长截断至最近句号,<150 字符丢弃。
- **B 详细 verbose**:以 `results/e0_basefix/` 100 条 base_goldfix 回答(均长 3250 字符)作 few-shot 模板,Moonshot 重写全部 completion,下限 1200 字符。
- **C 双风格(推荐)**:instruction 全量保留短答(≤400 字符,system 段"简洁模式:直接给出结论与要点,不超过 300 字"),按子集分层抽 40% 生成长答(1200–2500 字符,system 段"详细模式:给出完整的结构化分析,包含术语定义、推理过程与实施建议");同一 instruction 的长短两版同组同侧划分;训练样本数 = 短答 N + 长答 0.4N。

**论证**:【已证实】E0 证明 v1–v4 学到的是风格转换非能力提升(§2.1);completion 长度分布就是模型输出长度分布的先验(v4 concept 子集均长 277.4 字符 → 模型输出 ~285 字符,`experiments/e2/e2_data_attr.json`、`stats_review.md` §4.3)。【推断】推荐 C 的理由:① E0 遗留的长度混淆只有双风格模型能正面回答——同模型、同权重、仅 system prompt 不同的受控对比是 E0 §6 待办②的最干净实现;② 单风格是把鸡蛋放在一个 KPI 篮子里;③ API 增量约等于重生成 ~2,500 条 completion,远小于一次 7h 训练 run 的机会成本。

**风险**:C-1 长度分布模糊——风格指令放 system 段(v4 管线 prompt 由数据构建侧完整渲染),评测按风格分组报告,任一风格臂显著劣于 v2 即触发归因;C-2 长答重写噪声——同 §4.2 三规则清洗 + 10% 人工抽检。若选 A:接受 judge 轨差距大概率依旧;若选 B:须重测全部锚点,评测预算 ×1。

### 4.2 真实锚定:385 条种子 ×3 上采样 + 二次清洗三规则

**决策**:385 条种子显式注入训练集,每条 ×3;注入点在全部质量门之后、划分之前;种子与衍生物同 group id 划分,永不跨侧。注入前执行三条清洗规则(命中计数写入 manifest):

1. **同题不同答**:归一化 instruction 相同而 output 不同的冲突组整组丢弃(不投票);
2. **公式化收尾**:output 末 80 字符命中模板收尾黑名单者截去收尾句,截断后 <150 字符整条丢弃;清洗后残留率必须 =0;黑名单数据驱动(末 80 字符频次 ≥3 的串全部入列);
3. **超短回答**:output <150 字符整条丢弃。

**论证**:【已证实】v4 训练集 = v2 语料 10,327 条 + ariz boost 674 条(`evidence_table.md` ④),**385 条种子从未锚定过任何已评测模型**;三类缺陷均有文件记录(10 组同题不同答、模板收尾、26 条 <60 字符,`docs/training_retrospective_2026-07-20.md:51-52`);规则 1 已被 v4 门 2 实战验证(11,001 条输入丢弃 30 组/68 条,`evidence_table.md` ①)。【文献支持】等量真实 > 合成 +11.9%(arXiv:2602.04482 §6.6,741 条 agent 任务,语境限定见 §7);retrospective P1 第 1 条即"种子 2–3 倍上采样"(`training_retrospective_2026-07-20.md:129`)。【推断】取 ×3:~7,500 条训练集中 1,155 条等效样本占 ~15%,回到 DATA-02 目标下沿附近;超过 ×3 小样本重复过拟合风险盖过锚定收益。

**风险**:种子未经 TRIZ 专家审核——先过清洗,另抽 30 条送 TRIZ 顾问快审(Owner 裁决项 #4),错误率 >10% 降权至 ×2;泄漏——种子同样过双重去污门。

### 4.3 cap 门修复:术语覆盖优先 60% + 随机 40%,cap 1500→2500

**决策**:concept_explanation / innovation_assessment 两子集 cap 1500→2500;门内选取弃用"长答案优先",改两阶段:TRIZ 工具术语言表贪心最大覆盖选取(保底 60%)+ 剩余 40% 按 output 长度三桶分层随机。术语言表 v1.0:功能分析、矛盾矩阵、S曲线、40个发明原理、技术矛盾、物理矛盾、理想解/IFR、资源分析、物场分析、因果链、Functionality、Cost、改善参数、恶化参数、通用工程参数(构建时落 manifest)。

**论证**:【已证实】"长答案优先"把两子集从 3,527/3,311 砍到各 1,500,共丢 3,838 条 = 输入 34.9%;保留集显著更长(p=5.3e-25)但均长仅 277.4 vs 263.8 字符——为 +5% 长度漂移付了 2,027 条 concept 多样性(`experiments/e2/e2_data_attr.json`);E2 终判 8 词次真缺失与该门存在机制链,stats_review §4.3"不能排除清洗误伤术语多样性",工程启示⑤"质量门排序规则是训练信号"(`assessment_report.md` §三)。【推断】cap 2500 保留 ~71–75%,丢弃率降至 ~20% 以下;覆盖配额保证 15 词每词 ≥30 条(450 < 1500 可行);保留 40% 纯随机避免术语言表成为新选择偏差(v3 堆关键词教训,`stats_review.md` §3.2)。

**风险**:术语复读机——两轨决策门把关,kw 升 judge 降反向即回滚归因;训练集变大超时——7,500 条 ×2 epochs ≈ 1,875 步 ≈ 5.7h(11.0 s/step × batch 8),超时先砍 cap 至 2000 不砍 epochs。

### 4.4 Safety-Refusal 子集补齐 300 条

**决策**:新增 300 条(推荐值,区间 200–400),5 类各 60:① 超范围请求;② 危险工程操作;③ 诱导专利侵权/规避;④ 医疗/安监/环保合规结论;⑤ 索取客户保密信息。Moonshot API 同管线生成,过 §4.2 同标准清洗 + 10% 人工抽检;拒答模板 ≤3 种、每种 ≤5% 占比;每条 completion 须含"拒答理由 + 可替代的合规帮助方向"两段结构。占比硬上限 5%。

**论证**:【已证实】规划 400 条(7%),v1/v2 实为零(`training_retrospective_2026-07-20.md:58`);retrospective P1 明确要求补 200–400 条(:131)。【推断】300 条 ≈ 训练集 4%,回到规划下沿;拒答信号模式高度重复,边际收益递减快。

**风险**:过度拒答——金标评测新增 overrefusal 检查(100 题回答不得出现拒答模板,>2% 即决策门不过)+ general_probe 回归门(v1 曾 −0.133 显著退化,`evidence_table.md` ②-C)。

### 4.5 ariz 定向数据:保留存量、不追加增量、占比封顶 15%

**决策**:继承 v3 ariz boost 全部 594 条入训样本(674 − 80 评测预留,`evidence_table.md` ④),不追加第二轮 boost;ariz_guidance 占比封顶 15%,超限随机下采(优先丢与 v2 语料 Jaccard 相似度高者)。

**论证**:【已证实】金标 ariz 子集 v4 双轨四方最高(kw 0.7494 / judge 2.85,`evidence_table.md` ②-E);E3' rubric +0.083 [0.033,0.142] 显著;关键词漏判率 31.7% 证实"v2 ARIZ 回退"大部为伪影(`experiments/e3/e3_report.md`)。【已证实】v3 时代同批样本曾致两轨反向(kw +0.0556 [0.0010,0.1099] / judge −0.0682 [−0.1078,−0.0296],`stats_review.md` §3.2)。【推断】差异更可能来自训练配置与占比而非样本本身有毒;v4 ariz 占比 831/5,739 = 14.5% 已近上限,ariz 已是双轨最强子集,边际收益最小的方向不该再加重量;若未来要补,方向是 step6 覆盖(v4 唯一弱项 0.3)而非总量。

**风险**:封顶触发下采——检查金标 ariz kw ≥0.70 保持(v4 为 0.7494);同源评测高估——结论一律以金标 100 题(ariz n=20,独立 chunk 抽样)为准,eval2 扩充集仅作回归监测。

### 4.6 双重去污 + 划分交叉检查

**决策**:参照集 A = 金标 `v4_gold.jsonl` 100 题(沿用 v4 门 4);参照集 B = eval2 扩充集 `sample_data_expanded.json` 465 条 + `general_probe.json` 30 题(新增)。规则:token 3-gram Jaccard J ≥ 0.5 剔除;J ∈ [0.4,0.5) 人工审查队列;分层分组 85/10/5(seed=42),种子衍生物与长短双风格版同组同侧;划分后 test/validation 与 train 交叉检查,命中移回 train(v4 移回过 52 条);去污结果由**独立脚本复核**,数字写入 manifest。

**论证**:【已证实】v4 门 4 对金标 0 命中、门 6 移回 52 条,但 eval2 扩充集与 general_probe 从未进入任何一版的去污参照;assessment 诚实声明第 7 条"训练数据泄漏未独立检验"(`assessment_report.md` §七.7)——v5 把独立复核从声明变成机制。【推断】0.4–0.5 区间人工队列而非自动剔除:中文短问题术语天然高重叠,预计量级几十条;3-gram 沿用 v4 既有实现(11k 条秒级),不另引 embedding 去重。

**风险**:B 集 reference 与训练语料近缘可能误杀——命中计数分参照集报告,B 集剔除 >3% 触发人工复核;评测集变更后旧去污失效——manifest 记录参照集版本与 sha256,变更必重跑。

### 4.7 数据 manifest 制度化

**决策**:强制产物 `data/processed/v5_data/MANIFEST.md` + 构建报告 JSON,随 run 提交 git,缺一即构建失败:① 全部输入文件清单 + sha256;② 每道门命中/丢弃计数(v4 `v4_data_report.json` gates 结构 + 种子清洗三规则、术语覆盖明细、双重去污分参照集计数);③ 最终 train/validation/test 条数、子集分布、长度分布(mean/p50/p95)、风格配比;④ 划分参数与退化声明(v4 因语料无 source/chunk 标识降级为 instruction 前缀聚类,`evidence_table.md` ⑤-11,v5 须如实继承或修复);⑤ 输出 jsonl sha256、行数、对应 config 文件名与 git commit。

**论证**:【已证实】v1 的 2,662 条"无 manifest,无法复现到底是什么"(`training_retrospective_2026-07-20.md:56`);"548 vs 385"数字漂移残留 4 处文件;P1 要求 manifest 制度化 + 时间戳目录禁覆盖(:132)。v4 报告已是雏形,v5 增加种子链与双风格两维度并补 git 入库。

**风险**:manifest 手写滞后——构建脚本自动生成,里程碑关闭加"文档新鲜度"硬门槛;远端单点——构建完成即 commit + push,manifest 入库是训练启动的前置条件。

### 4.8 数据侧接口声明

- **对训练**:交付 v5_train/validation/test.jsonl(prompt/completion 格式,沿用 v4 schema);若裁决为 C,prompt system 段含风格指令,训练侧不得二次渲染;训练时长按 ~7,500 条 ×2 epochs ≈ 5.7h 估算。
- **对评测**:保证金标 100 题 + eval2 扩充集 495 题双重去污;若裁决为 C,金标按两个 system 变体各跑一遍(生成预算 ×2);overrefusal 检查与术语覆盖回归依赖评测 harness 各加一项检查。

### 5.2 关键决策论证(删减版,逐项"决策—证据—风险")

**① lr 默认 2e-4、六组小扫终裁**。【已证实】四轮全部 2e-4 稳定收敛(v4 mean_token_accuracy 0.3954→0.6889、v2 0.4813→0.7919,`evidence_table.md` ③);但 v4 cosine 按 max_steps=2,872 设计,step 1,000 早停时 lr 仍有 1.553e-4,全程未进退火段——"2e-4 是否过高"开放未答(⑤-11)。【文献支持】LoRA 对 lr 最敏感(Biderman et al. 2024, arXiv:2405.09673);lr × rsLoRA 六组小扫处方早在 v2 规划期开出至今未执行(`training_retrospective_2026-07-20.md:139`)。**风险**:0.5 epoch 短跑偏好高 lr——判据要求 top-2 臂过 40 题金标双轨冒烟,不允许仅凭 loss 锁定(v3 eval_loss ≈ v2 但 judge 显著更差的教训)。

**② rsLoRA 默认 False,与 lr 联合网格**。【已证实】`config.py:65` 自注"大 rank 时建议开启 rsLoRA",四轮未开,是悬置配置债。【文献支持】rsLoRA(α/√r,Kalajdzievski 2023, arXiv:2312.03732)解决高 rank 学习率塌缩;r=64 α=128 下标准缩放 2 vs rsLoRA 16,同 lr 有效更新放大 8 倍,故必须 3×2 联合网格。**风险**:rsLoRA 臂短跑占优但后段过拟合——胜出则主 run 沿用同一早停/best 制度,adapter_info.json 显式记录 use_rslora 与缩放因子,防跨代混读。

**③ cosine horizon 2 epoch,num_train_epochs=4 仅安全帽**。【已证实】四条 eval_loss 轨迹一致指向最优点 ≤2 epoch:v1 欠训练(best 在末步);v2 best 1.0673376321792603 @ step 2000 ≈ 1.89 epoch;v3 best 1.0705283880233765 @ step 1100 ≈ 0.98 epoch 后回升;v4 best 1.5592304468154907 @ eval_step 700 ≈ 0.98 epoch(`evidence_table.md` ①)。2-epoch horizon 下 v4 规模 run 将在 step ~1,436 完成退火,罩住 0.98 与 1.89 两端。**风险**:v5 数据显著扩量且多样性更高时或略欠训练——horizon 末段 eval_loss 仍显著下降为可观测信号,复跑调至 3 epoch 并记录理由。

**④ 12 模块 target_modules 不变;routed expert 不接是"已知且接受"的边界**。【已证实】清单为 Qwen3.6 混合架构手工全线性层覆盖(q/k/v/o_proj + in_proj_qkv/z/b/a + out_proj + gate/up/down_proj,`config.py:51-61`);LoRA 仅覆盖 84.66M/34.7B = 0.24% 参数,expert 主体未触——与 E0"风格转换由注意力与共享投影承载、知识存于未触 expert"的图景自洽;v4 同清单训练稳定,adapter 620 tensors 全 BF16 非零。【文献支持】MoE 上"非越多越接越好"(MoE-Sieve arXiv:2603.24044 只接 top-25% expert 即可相当);256 expert 挂 LoRA 显存成倍膨胀且无本项目证据表明必要。E5 模块消融后置(§5.3 P2a)。

**⑤ 纯 BF16 不量化终裁 + 容量规则**。【已证实】4-bit 双重事故史(名义 QLoRA 与实际 FP16 不符、加载 62.61GB 远超预期,`evidence_table.md` ⑤-13;`pipeline_v4_remote/README.md` 事故 #6);121GB 统一内存下 35B BF16 ~70GB 在容量内(推理峰值四轮稳定 64.68–65.22GB)。【推断】容量规则写入配置 `_notes`:BF16 适用基座 ≤ ~50B;超过切 NVFP4/QLoRA 且必须逐模块量化审计。

**⑥ completion-only loss 维持 + 断言 + 启动冒烟**。【已证实】全文计 loss 是 v1–v3 硬伤 1;trl 1.5.1 prompt/completion 格式自动启用 completion_only_loss(源码机制经确认);口径切换代价已记录(v4 best 1.5592 与 v2 1.0673 不可比,`evidence_table.md` ⑤-1),v5 沿用 = 与 v4 直接可比;chat template 无 `{% generation %}` 曾致静默失效(事故 #5)。**新增硬化**:断言之外加启动冒烟——decode 首个 batch 的 labels,确认 prompt 区段全为 -100(防自动判定规则变更的共模失效);环境固定 venv_v5(peft 0.19.1 / transformers 5.10.1 / trl 1.5.1 / torch 2.12.0)与 v4 完全相同。

**⑦ max_length=2048 断言项**。【已证实】v1 时代静默截断疑似硬伤 2;v4 门 7(>2048 token 丢弃)实际丢弃 0 条,语料 p100 ≤ 2048;`config.py:140` 的 4096 属死配置不引用。**风险**:若 v5 数据 p99 > 2048(如裁决 B/C 长答),报 Owner 裁决是否升 3072,默认不升(开放项 #15)。

**⑧ best-checkpoint 制度全量保留**。【已证实】每条对应真实事故(save_total_limit=3 轮转删最优、内存态污染 fallback 保存 310 个全零 lora_B——v3 发货事故根因);v4 实战正向验证:best 连续晋升 step100→700,发货 = best @ 700 而非早停末步 1,000——没有该制度发出的将是 eval_loss 已回升 300 步的退化权重。

**⑨ 早停 patience=3 + min_delta=0.002**。【已证实】patience=3 在 v4 按设计工作(actual_epochs=1.393);v2 平台期逐次波动 ~0.0002,threshold=0 会把噪声当真改善;取 0.002 = 噪声 10 倍,远小于真改善速率(v2 后期 ~0.005/100 步,边距 2.5 倍)。【推断】0.002 具体取值无项目直接实证,属参数化补齐;误触发时 best-checkpoint 制度兜底,方向安全。

### 5.3 训练侧验证路线(执行顺序与判据)

**原则:先锁超参(P0)→ 主 run(P1)→ 条件消融后置(P2)。GPU 串行排队,单 run 期间不并行其他 GPU 任务。**

- **P0 lr × rsLoRA 六组小扫(必做)**:lr ∈ {1e-4, 2e-4, 5e-4} × use_rslora ∈ {False, True},各 0.5 epoch(⌈D/8⌉/2 步),其余与总表全同,eval_steps=50。**判据两阶段**:初筛终点 eval_loss 最低(与 2e-4/False 差 ≤0.01 视为平局);终判 top-2 臂各做 40 题金标双轨冒烟(分层抽样,judge=moonshot-v1-32k,T=0,AB/BA 双序合并),选 judge 更高且 kw 无显著退化者;仍平局取 2e-4/False。成本 6 run × ~1.1h ≈ 6.6h(D≈5.7K;D≈8.5K 时 ~9.7h)+ 冒烟 ~1h + judge API ~0.5h。
- **P1 v5 主 run(核心交付)**:P0 锁定配置,cosine 2-epoch horizon;训练后走金标双轨评测 + 决策门 2.0(§6.7),对手 v2 与 base_goldfix;凡非 `base_goldfix` 谱系 tag 的 base 缓存一律视为受污染。成本 ≤7h 预算帽(按 v3/v4 轨迹预计 2.5–4h 早停)+ 评测 ~1h + API ~0.5h。
- **P2a E5 模块消融(条件)**:仅 Attention vs 仅 DeltaNet 两个 1-epoch 短 run。**不改变 v5**,改变的是 v6 与论文贡献 A 的消融证据;仅当 v5 主 run 出现未预期退化时提前为诊断工具。成本 ~6.4h GPU(含评测)。
- **P2b E4 数据门消融(条件)**:v5 数据门相对 v4 有变更(本方案 §4.3 cap 门即变更)时启动:新门开/关两个 run,重点盯 concept_explanation kw 轨。成本 ~16h GPU(完整版)。启动与否由 Owner 按预算裁决(开放项 #14);`assessment_report.md` §5.2 原判"暂缓"。

## 6. 评测协议与决策门 2.0(支柱三合并)

> 核心教训:v1→v4 最大的失败不是训练失败,而是决策门被污染锚点误导。本节的全部设计回答一个问题:**如何让决策门在下一次测量事故、双轨分歧、偏差面前依然给出正确判定。**

### 6.0 设计原则

P0 锚点先行(E0:91/100 草稿)| P1 双轨并判(两轨 r≈0.32,仅共享 ~10% 方差,`stats_review.md` §3.1)| P2 双序合并(单序一律无效,E1a 位置不一致率 0.87 [0.790,0.922])| P3 功效自觉(每结论附 MDE,功效不足标"描述性")| P4 统计可复现(固定实现、固定 seed,stdlib 与 numpy RNG 存在千分位差异,`stats_review.md` §1)。

### 6.1 干净锚点协议

- **harness 永远保留空 think 块**:render_prompt 保留 chat template 渲染的 `<think>\n\n</think>\n\n`,禁止后处理剥离;生成完成后才允许剥离闭合 think 块。写入单元测试(3 题冒烟断言中文正式作答)。【已证实】E0 诊断矩阵中"保留空 think 块"是唯一成功路径(3/3),assistant prefill 与 bad_words_ids 均失败(`E0_report.md` §2)——这是 thinking-native 基座的必要生成条件,非可选优化。
- **生成后四道质量门**(评分前执行,任一不过标记 invalid 并触发一次 bad_words_ids 兜底重生成,仍不过计入失败率并冻结评测):① think 残留检测;② 非空;③ 中文占比 ≥0.3;④ 长度 ≥100 字符(微调模型追加"≥50 字符且不低于同题 base 长度 3%")。质量门汇总须出现在每份评测报告首页。【已证实】E0 修复脚本即此套门:100/100 mode=direct、0 兜底、0 invalid、长度 1246–4080 均值 3250 字符(`E0_report.md` §3)。
- **base 锚点每次重验,污染缓存一票否决**:评测启动前 3 题冒烟 + 缓存 tag 校验(必须 `base_goldfix` 谱系);v5 评测时 base 锚点**重新生成一次**(同 harness、同 token 预算、同批次),与旧缓存逐题一致性检查(kw 分差 |Δ|>0.2 的题数 >10% 冻结报警);保留双锚点报告,结论不一致时以同 harness 新锚点为准。【已证实】污染代价是反号级(+1.00 → −0.30,McNemar 55/4 p=1.7e-12 → 10/30 p=0.0022 反方向,`E0_report.md` §4.3)。

### 6.2 双轨制升级

- **关键词轨别名表回流**:匹配升级为"子串 + KEYWORD_MAP 别名表";每轮评测后漏判审计(rubric ≥0.5 而 kw <0.5 的题逐条提取漏判表述,人工确认后写入 `keyword_map_v5.json`);报告同时给"别名表更新前/后"双分数。【已证实】E3 漏判率 31.7%(19/60),几乎全是英文步骤名/同义表述(19 条清单可审计);反向高估仅 1/60。**纪律**:每条别名须 ≥2 个漏判案例或人工确认;漏判率 <5% 后冻结别名表;历史数字不重写。
- **两轨分歧裁决规则**:R1 能力声明以语义轨为准(kw 显著正 + 语义不显著 → 不得声明提升);R2 kw 显著退化须先做 E2 式归因,真缺失 → 退化成立,伪影 → 语义轨为准;R3 两轨显著反向默认回滚 + 归因,禁止单轨翻盘;R4 ariz 子集两轨分歧时 rubric 无条件优先(依据 E3 漏判率实测,仅适用 ariz 单个子集)。

### 6.3 pairwise 一律 AB/BA 双序

一切 pairwise 必须双序;报告 = 合并胜率 [Wilson 95%CI] + 位置不一致率 + B 位胜率,三数齐全才有效;**不一致率 >10% 时任何单序数字作废**;≤10% 仍须双序(防选择性执行)。【已证实】E1a:AB 序 v4 胜率 0.180 vs BA 序 0.800,摆动 62pp——文献均值 25pp 的两倍多,双序是必需品。pairwise 仅用于决策门终审与关键对比(≤400 裁决/轮),rubric 点值轨不双序。

### 6.4 judge 纪律

- **T=0 锁定**:温度硬编码断言;换 judge/换任务后先 40 题 × 5 次翻转率冒烟(>2% 才允许多次投票);每轮随机抽 10 题重复裁决,翻转率 >0 报警。【已证实】E1c:T=0 翻转率 0.0000(80 cell 全一致)。
- **版本钉死**:v5 全周期 judge = moonshot-v1-32k;回退链 `kimi-k2-0711-preview → moonshot-v1-32k → moonshot-v1-8k`,偏离须报告首页红色标注;跨 judge 版本只比"同 judge 下的模型间差值"。【已证实】E1b:v4−base 差值 32k 为 −0.30、8k 为 −0.11——judge 版本是效应量的一部分。
- **异源评委终审**:决策门终审必须含 ≥1 个真异源评委(推荐 GPT-4o,备选 Claude/DeepSeek),对金标全集 × {base, v2, v5} 重评(~600 裁决);判据:关键对比排序与差值符号保持,且 v5−base 差值相对主评委缩水 <50%;同族评委(如 kimi 系列)必须声明"同族弱异源"。【已证实】训练语料 100% Moonshot 生成、金标 moonshot-v1-8k、主评委 32k——数据、金标、评委同族(`stats_review.md` §7.1);E1b 的"异源"实为同族弱异源;工程启示③"换了个同族小弟不算异源验证"(`assessment_report.md` §E1b)。
- **长度控制双臂 judge**(决策门输入,两臂均须报告):
  - **臂 A 长度归一化 judge**:rubric 加显式反冗长条款("回答长度本身不构成加分项,冗余重复内容在 completeness 维度扣分");judge 输入不截断(消除 1500 字符截断不对称——旧截断下 base 仅 ~46% 可见,即 base 真实优势可能比 −0.30 更大);
  - **臂 B 同长度桶对比**:<500 / 500–1500 / 1500–3000 / >3000 字符分桶,只在同桶内配对;v5 vs base 不同桶时报告"无同桶配对"并以臂 A 为准;臂 B 主用于 v5 vs v2(同 ~300 字符,同桶高功效)。
  两臂结论冲突 → 冻结判定 + 人工抽检 20 题。臂 A rubric 先在 v4 缓存试跑,v4−base 差值移动 >±0.15 时人工校准后再上决策门(开放项 #12)。

### 6.5 金标集扩充 100 → 200 题

原 100 题(`v4_gold_001–100`)钉住不动保历史可比;新增 100 题(`v5_gold_101–200`)按 6 子集等比(principle +20 / contradiction +20 / ariz +20 / case +15 / concept +15 / innovation +10),沿用 v4 金标管线 + 人工抽检 10%;新增题必须对 **v5 新语料**重跑去污门(J≥0.5 丢弃)。【已证实】n=100 时 overall judge MDE 0.279、kw MDE 0.088;100→102 几乎无改善(`stats_review.md` §6.1)。【推断】n=200 外推:overall judge MDE ≈ **0.197**、kw ≈ **0.062**、McNemar 可分辨 ~13–15pp;子集结论依然描述性(扩充收益在 overall 与 McNemar,报告须如实说明)。所有对比同时报"钉住层 n=100"与"全集 n=200"双口径,决策门以全集为准,两口径冲突冻结归因。

### 6.6 通用回归探针 30 → 120 题(E6 并入常设门)

6 类 ×20(常识/数学/逻辑/写作/代码/指令跟随),沿用 `general_probe.json` schema;写作与指令跟随加 rubric judge 轨;固化为每轮必跑回归门;每份报告强制输出探针 MDE。【已证实】n=30 MDE 0.093,现有"不显著"均为功效不足型(`stats_review.md` §6.3/6.4);v1 曾在该探针显著退化 −0.133,证明探针能抓灾难性遗忘。【推断】n=120 外推 MDE ≈ **0.047**——与"通用损失 <3%"KPI 存在 1.7pp 缺口,请 Owner 裁决(开放项 #9,推荐 KPI 改写为 <5pp)。

### 6.7 决策门 2.0(全部可机检,无自由裁量)

v5 替代 v2 发货,须**同时**通过 7 道判据(评测集 = 金标 200 题 + 探针 120 题;锚点 = 经重验的 base_goldfix 谱系):

| 门 | 判据 | 数值阈值 |
|---|---|---|
| G1 | judge 轨 vs 干净 base(臂 A;臂 B 不矛盾) | v5−base overall 差值 CI 下限 **> −0.15** |
| G2 | judge 轨 vs v2(增量必要性) | v5−v2 overall CI 下限 **> −0.05**,且 judge/kw 至少一轨显著为正 |
| G3 | 关键词轨退化禁令 | 任一子集 v5−v2 kw CI 上限 < 0 → E2 式归因;真缺失 → 拒绝;伪影 → 语义轨裁决后可放行 |
| G4 | 子集退化容忍度 | n<30 子集标"描述性"不独立否决;但该子集 judge 轨同向显著为负时与 G3 合并视为真退化 |
| G5 | ARIZ 语义轨优先 | ariz 两轨分歧以 rubric 轨为准 |
| G6 | 通用探针回归门 | v5−v2 探针 overall **> −5pp**(120 题 MDE ≈4.7pp) |
| G7 | 双轨反向熔断 | 任一维度两轨显著反向 → 默认回滚 + 归因 |

**阈值对账**:G1 −0.15 = v4/v2 对 base −0.30/−0.29 压缩一半的最小实质进展声明;n=200 MDE≈0.197 在功效边缘,故要求臂 B 不矛盾。G2 直接来自 v4≈v2 无增量教训;±0.05 在 kw 轨实用等价界内(`stats_review.md` §6.4-1)。G3/G4 沿用 v4 决策门机制 + E2 归因教训 + 功效现实。G5 依据 E3(+0.083 显著 vs 漏判率 31.7%)。G6 依据 E6 设计。G7 = 工程启示⑦原文。

**G1 判不出的加赛授权**(开放项 #11):点值 > −0.15 但 CI 下限未过线 → 允许一次加赛(n→300,MDE≈0.161),仍不过则保留 v2;或接受"G1 降级描述性通过 + 其余门全过"由 Owner 终裁。

**回溯验证(门设计验收测试)**:v4 代入 → G1 不过(CI 上限已低于 −0.15,且新门先要求补跑双臂再判)、G2 不过(−0.01 [−0.13,+0.11] 无增量)、G3 不过(CE 真退化 8 词次)→ 综合判"拒绝 v4 替代 v2"——与 E0 实际结论一致但理由更完备,并额外产出行动项"补长度控制臂"。**新门在已知案例上判对且更透明**。v5 首轮评测时以 v2 vs base(eval2 口径 +0.0736 [0.0310,0.1162])作"准正例"做第二轮回溯。

### 6.8 统计纪律(八条,写入评测脚本断言)

① 配对 bootstrap 10,000 次、seed=42、钉死 stdlib `random.Random(42)`(禁 numpy RNG,两者千分位 CI 差异已实测);② McNemar 精确双侧(复算验证至 p=1.6979681549678105e-12 逐位一致);③ Wilson 95% CI 用于一切比例;④ seed/配置/judge 版本/温度/截断长度/锚点 tag 入报告 meta;⑤ n<30 子集结论标"描述性(n=X,MDE=Y)";⑥ MDE 随 CI 同报,CI 半宽 >±0.05(kw)/±0.13(judge)禁用"等价"措辞;⑦ 每份报告附"功效不足结论清单";⑧ 逐题明细 jsonl 落盘可逐位对账。执行保障:脚本内置 bootstrap 实现指纹校验,报告生成器自动插入 MDE 与"描述性"标注。
