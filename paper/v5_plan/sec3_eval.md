# v5 方案 · 支柱三(W3):评测协议与决策门 2.0 重设计

> 执笔:W3 评测与决策门设计师 ｜ 日期:2026-07-25 ｜ 产出:`paper/v5_plan/sec3_eval.md`
> 证据强度标注:【已证实】= 本项目统计检验终稿数字;【文献支持】= 外部文献结论,本项目未独立复现;【推断】= 由已证实证据外推的设计判断。
> 核心教训:v1→v4 最大的失败不是训练失败,而是**决策门被污染锚点误导**——旧决策门在 base 草稿污染下判出"+1.00 显著提升"的伪影结论(E0 §4.3:+1.00 [0.80,1.19] → 干净锚点 −0.30 [−0.46,−0.14] 反号)。本支柱的全部设计都围绕一个问题:**如何让 v5 的决策门在下一次测量事故、下一次双轨分歧、下一次偏差面前依然给出正确判定。**

## 0. 设计原则总览

## 1. 干净锚点协议(Clean Anchor Protocol)

### 决策 1.1:harness 永远保留空 think 块,禁止在 `enable_thinking=False` 渲染后剥离

**决策**:v5 评测 harness 的 `render_prompt` 必须保留 chat template 渲染出的空 think 块 `<think>\n\n</think>\n\n`;禁止任何后处理剥离。生成完成后才允许剥离闭合 think 块。该规则写入 harness 单元测试:对 Qwen3.6-35B-A3B 基座跑 3 题冒烟,断言输出为中文正式作答。

**论证**:【已证实】E0 根因定位——`eval_harness.py:render_prompt` 在 `apply_chat_template(enable_thinking=False)` 之后把空 think 块剥掉,thinking-native 基座失去"思考已结束"锚点,100/100 自吐英文 think 草稿;诊断矩阵 4 策略中"保留空 think 块"是唯一成功路径(3/3 正常中文结构化作答),assistant prefill 与 bad_words_ids 两种强制手段均失败(`experiments/e0/E0_report.md` §2)。这不是可选优化,是 Qwen3.6 这类 thinking-native 基座的**必要生成条件**。

**风险与缓解**:风险①——未来换基座(非 thinking-native)时该规则可能多余甚至有害;缓解:协议写成"thinking-native 模型专用分支",按模型 config 的 chat template 是否含 think 结构自动判定,并在评测报告 meta 中记录分支选择。风险②——v2/v4 等微调模型的 adapter 已学会不吐 think(v2/v4 响应 0/100 含 think,`stats_review.md` §2.1-2),保留空 think 块对其无影响,但仍需冒烟确认。

### 决策 1.2:生成后质量门(think 残留检测 + 非中文检测 + 长度下限)

**决策**:每次生成后、评分前,对每条响应执行四道质量门,任一不过则该条标记 invalid 并触发一次 bad_words_ids 兜底重生成,仍不过则计入质量门失败率并冻结评测:
1. **think 残留检测**:剥离闭合 think 块后,响应中不得再出现 `<think>` 字样;
2. **非空校验**:剥离后正文非空;
3. **中文占比 ≥ 0.3**(中文字符数/总字符数);
4. **长度下限 ≥ 100 字符**。
生成质量门汇总(mode 分布、兜底次数、invalid 数、长度 min/mean/max)必须出现在每份评测报告首页。

**论证**:【已证实】E0 修复脚本 `e0_gen_basefix.py` 即采用此套门(max_new_tokens=2048、生成后剥离闭合 think、非空 + 中文占比 ≥0.3 校验、bad_words_ids 兜底一次),修复后 100/100 mode=direct、0 兜底、0 invalid、无 think 残留、无过短、长度 1246–4080 均值 3250 字符(`experiments/e0/E0_report.md` §3、§4.1)。反例:污染版 base 的 91/100 草稿若经过这套门,会在"非空校验 + 中文占比"处全部拦截——**质量门的价值正是把 E0 级事故从"评测后发现"提前到"评分前拦截"**。

**风险与缓解**:风险——阈值 0.3 与 100 字符是 E0 场景下的经验值,对 v5 微调模型(~300 字符短答)过松;缓解:对微调模型追加"长度下限 ≥ 50 字符且不得低于同题 base 长度的 3%"(v2/v4 均长 ~300 字符 vs base 3250,3% ≈ 98 字符,兼容现状),并逐版本人工抽检 5 条门边界样本。

### 决策 1.3:base 锚点每次评测必须重验,污染缓存一票否决

**决策**:① 每次金标评测启动前,base 锚点缓存必须通过"锚点重验":3 题冒烟(结构完整性:think 闭合、有正式答案、中文)+ 缓存 tag 校验(必须为 `base_goldfix` 谱系);② 任何输入含"base 对金标题的回答"的分析,在核对缓存 mtime/tag 之前一律视为受污染,不得进入统计;③ v5 评测时 base 锚点**重新生成一次**(而非复用 v4 缓存),与 v5 同 harness、同 token 预算、同批次,重生成后与 `base_goldfix` 缓存做逐题一致性检查(kw 分差 |Δ|>0.2 的题数 >10% 时冻结评测并报警)。

**论证**:【已证实】E0 §5 确立的通用原则:"凡输入包含 base 模型对 100 金标题的回答的分析,在核对所用缓存文件 mtime/tag 不是 base_goldfix 之前,一律视为受污染"(`experiments/e0/E0_report.md` §5)。污染的代价是反号级:v4−base judge +1.00 [+0.80,+1.19] → −0.30 [−0.46,−0.14],McNemar 55/4 p=1.7e-12 → 10/30 p=0.0022 反方向显著(E0 §4.3)。【推断】v5 重新生成而非复用缓存的理由:harness 在 v5 周期内必然被修改(本支柱 §1.1–1.2 就是修改),同 harness 重生成可消除"harness 版本 × 模型版本"交互混淆;成本仅 ~1h GPU(base 100–200 题 × 2048 tok),相对一次 v4 级训练 7h 可忽略。

**风险与缓解**:风险——重新生成的 base 与旧缓存存在采样/实现漂移,可能造成"v5 vs base"与"v4 vs base"锚点不可比;缓解:保留双锚点报告(v5 vs base_goldfix 缓存、v5 vs base_v5 新生成),两者结论不一致时以同 harness 新锚点为准并记录差异。

## 2. 双轨制升级:关键词轨 + rubric 语义轨

### 决策 2.1:关键词轨引入"别名表回流"机制,每轮评测后强制回流

**决策**:关键词轨评分器升级:① 期望关键词匹配从"大小写不敏感子串"升级为"子串 + KEYWORD_MAP 别名表匹配";② 每轮评测后执行**漏判审计**:对 rubric 轨 ≥0.5 而 kw <0.5 的题,逐条提取漏判表述,人工确认后写入 KEYWORD_MAP(中英别名、同义表述、英文步骤名),并标注来源题号;③ 别名表版本化(`keyword_map_v5.json`),每次变更触发金标集 kw 轨全量重打分,报告中同时给出"别名表更新前/后"两个 kw 分数。

**论证**:【已证实】E3 实测关键词漏判率 **31.7%**(19/60,rubric≥0.5 而 kw<0.5),反向高估仅 1/60;漏判几乎全是"英文步骤名/同义表述"——如期望词"资源分析"被写成 "Resource Analysis"、"理想解"写成 "IFR (Ideal Final Result)"(`experiments/e3/e3_report.md` 漏判清单 19 条)。【文献支持】关键词误判案例回流是评测方法学研究的第 3 号建议("每轮人工抽 5-10 题核对,把漏判的同义表述补进 KEYWORD_MAP",`eval_methodology_research.md:81`);BLEU/ROUGE/EM 类表面重叠指标对语义等价改述的系统性误判在文献中问题记录最充分(`eval_methodology_research.md` §2.1)。【推断】"更新前/后双分数"设计防止别名表被悄悄调参到过拟合评测集——这是指标治理,不是指标优化。

**风险与缓解**:风险①——别名表无限膨胀导致 kw 轨失去区分度(所有回答都命中);缓解:每条别名须由至少 2 个漏判案例支撑或由人工确认,且每轮报告漏判率变化,漏判率降至 <5% 后冻结别名表。风险②——别名表回流改变历史可比性;缓解:历史版本数字不重写,v5 报告同时列"冻结表口径"与"最新表口径"。

### 决策 2.2:两轨分歧裁决规则——语义轨优先,但关键词轨保留"退化一票"与归因义务

**决策**:任何维度两轨分歧时,按以下规则裁决(决策门 2.0 的组成部分,见 §7):
- **R1(能力声明)**:凡"模型能力提升/优势"的声明,以 rubric/judge 语义轨为准;关键词轨显著为正但语义轨不显著时,不得声明提升。
- **R2(退化判定)**:关键词轨显著退化不得直接判退货,必须先做 E2 式归因(真缺失 vs 表述伪影);判为真缺失 → 退化成立;判为伪影 → 以语义轨为准。
- **R3(两轨反向)**:两轨显著反向时默认回滚 + 启动归因实验,不允许任一轨单独翻盘。
- **R4(ARIZ 专项)**:ariz 子集两轨分歧时,rubric 语义轨无条件优先(ARIZ 语义轨优先条款)。

**论证**:【已证实】三个案例各自支撑一条规则——
- R1/R4 由 E3 支撑:"v2 ARIZ 回退"在 rubric 轨下消失(v2 rubric 0.875 vs base 草稿 0.675;干净臂 E3' base_goldfix 0.800 / v2 0.875 / v4 0.883),证实为关键词伪影;且 v4 vs 干净 base rubric +0.083 [0.033,0.142] 显著,是最稳健的正面发现(`experiments/e3/e3_report.md`;`assessment_report.md` §E3)。
- R2 由 E2 支撑:v4 concept_explanation 的 kw 退化 −0.083 [−0.148,−0.023](n=15)经归因终判为**真缺失 8 词次、synonym 伪影 0 条**(功能分析×3、矛盾矩阵、S曲线等),但 judge 重判 v4 vs v2 +0.07 [−0.2,0.33] 持平——"真缺失但语义无损"的中间形态,说明 kw 退化不能绕过归因直接判退货,也不能因 judge 持平直接豁免(`experiments/e2/e2_report.json`;`assessment_report.md` §E2)。
- R3 由 v3 事故支撑:v3 vs v2 关键词轨 +0.0556 [0.0010,0.1099] 显著为正、judge 轨 −0.0682 [−0.1078,−0.0296] 显著为负,事后解剖证实 v3"学会了堆关键词,语义质量反降"("仅kw过"高达 31 题)(`evidence_table.md` ②-C;`stats_review.md` §3.2)。若当时决策门只听 kw 轨,v3 会被误判为进步。
- 方法学总依据:两轨只共享约 10% 方差(合并 400 题 r=+0.325),测的是两个不同构念——表层词汇对齐 vs 语义质量(`stats_review.md` §3.1);工程启示⑦:"发布/回滚决策门必须双轨化,单轨显著不得独立下判"(`assessment_report.md` §三)。

**风险与缓解**:风险——R4"ARIZ 无条件语义优先"可能被质疑为结果导向的特设条款;缓解:该条款的正当性来自 E3 的 31.7% 漏判率实测与 19 条漏判清单(可审计证据),且条款只适用于 ariz 单个子集,写入决策门时附 E3 引用;其他子集分歧仍走 R1–R3 通用流程。

## 3. pairwise 一律 AB/BA 双序

### 决策 3.1:双序强制 + 合并胜率口径 + 不一致率作废线

**决策**:v5 一切 pairwise 比较(含决策门内的胜率判据)必须 AB/BA 双序执行;报告口径 = 双序合并胜率 [Wilson 95%CI] + 位置不一致率 + B 位胜率,三数齐全才有效;**位置不一致率 >10% 时,任何单序数字作废**,且该对比只允许引用合并值;不一致率 ≤10% 时仍需双序(防止"先跑单序看不一致再补跑"的选择性执行)。

**论证**:【已证实】E1a:AB 序 v4 胜率 0.180 [0.117,0.267] vs BA 序 0.800 [0.711,0.867],位置不一致率 0.870 [0.790,0.922],硬翻转率 0.770,B 位总胜率 0.81——单序结论完全由位置决定;干净臂 E1a' 不一致率仍为 0.580(B 位胜率 0.650),双序合并后 v4 胜率 0.260 [0.204,0.325] 才给出"显著输给干净 base"的有效结论(`experiments/e1/e1_report.md`)。【文献支持】位置偏差可使胜率摆动达 25pp(Wang et al. 2023,`eval_methodology_research.md:44`)——我们实测摆动 62pp(0.180→0.800),是文献量级的两倍多,说明本任务的位置偏差比文献均值更严重,双序不是保险而是必需品。【推断】>10% 作废线沿用 E1a 既有判定阈值(E1a 报告原文"位置不一致率 >10%, judge 轨数字须以双序平均重报"),保持口径连续。

**风险与缓解**:风险①——双序使 pairwise API 成本翻倍;缓解:pairwise 仅用于决策门终审与论文关键对比(预计 ≤400 裁决/轮),点值评分轨(rubric 0–4)不双序。风险②——不一致率本身在小样本下噪声大;缓解:不一致率附 Wilson CI,n<50 时作废判定标"描述性"。

## 4. judge 纪律

### 决策 4.1:T=0 锁定,禁止任何非零温度;换 judge/换任务必须重验确定性

**决策**:全部 judge 调用 temperature=0;评测脚本中温度参数硬编码断言(非 0 即拒绝运行);每次更换 judge 模型或任务类型后,先用 E1c 范式做 40 题 × 5 次翻转率冒烟,翻转率 >2% 才允许多次投票,否则单次裁决。

**论证**:【已证实】E1c:T=0 下平均翻转率 **0.0000**(80 cell 全一致,k=1/3/5 多数表决一致率均 1.000),API 在该任务上完全确定;T=0.7 翻转率 0.0150,仍远低于文献 13.6%(`experiments/e1/e1_report.md`)。【文献支持】文献均值翻转率 13.6%、需 ~11 次投票才能 95% 复现参考裁决(arXiv:2606.13685,`eval_methodology_research.md:46-47`);缓解措施公认有效项含"温度 0、固定评委模型版本"(`eval_methodology_research.md:48-49`)。工程启示④:"T=0 + rubric 锚定下单次裁决即可信,不必浪费 API 做多次投票;但须每换一个 judge/任务重新验证确定性,不可默认"(`assessment_report.md` §E1c)。

**风险与缓解**:风险——T=0 的确定性可能是当前 API 实现细节(服务端缓存/确定性解码),供应商侧变更会静默破坏;缓解:每轮评测随机抽 10 题重复裁决一次,翻转率 >0 即报警(成本 10 裁决,可忽略)。

### 决策 4.2:judge 版本钉死 + 跨版本不可比声明

**决策**:v5 全周期 judge 钉死 moonshot-v1-32k(与 v4 金标/E0/E1 同版,保证历史可比);每份报告 meta 记录 judge 模型字符串、探测顺序与兜底链;若 32k 不可用,按 `kimi-k2-0711-preview → moonshot-v1-32k → moonshot-v1-8k` 探测顺序回退并在报告首页红色标注"judge 版本偏离";任何跨 judge 版本的分数比较一律禁止,只比较"同 judge 下的模型间差值"。

**论证**:【已证实】本项目已有三套不可互比的评测体系:修复版四连 / eval2(moonshot-v1-8k)/ 金标终报(moonshot-v1-32k),权重、评测集、judge 均不同(`evidence_table.md` ⑤-9);eval2 与金标的 judge 版本差异已被列为口径注意事项(`evidence_table.md` ⑤-3)。【已证实】跨评委即使同族也有系统性偏差:干净臂 E1b 中 v4−base 差值 moonshot-v1-32k 为 −0.30 [−0.46,−0.14]、moonshot-v1-8k 为 −0.11,幅度差近 3 倍(`experiments/e1/e1_report.md` E1b 补臂)——judge 版本是效应量的一部分,不是中性测量工具。

**风险与缓解**:风险——钉死旧版 judge 可能错过供应商模型升级带来的评委质量提升;缓解:每季度用 E1b 范式做一次"新旧 judge 平行重评"(300 裁决 ≈25 min),仅当逐题 Spearman ρ>0.9 且关键差值符号一致率 >0.9 时才允许升级,升级后全量重评金标缓存。

### 决策 4.3:异源评委终审——真异源(GPT/Claude 家族),同族弱异源必须声明

**决策**:v5 决策门终审必须包含 ≥1 个**真异源**评委(推荐:GPT-4o 或 Claude 家族一席;备选 DeepSeek),对金标全集 × {base, v2, v5} 重评(200 题口径下 ~600 裁决);终审判据:v5 相关关键对比的**排序与差值符号**在异源评委下保持,且 v5−base 差值相对主评委的缩水 <50%(沿用 W3 §7.3 阈值);若使用任何同族评委(如 kimi 系列),报告必须显式声明"同族弱异源,非完全异源"。

**论证**:【已证实】本项目结构性同源风险:训练语料 100% 由 Moonshot 生成(`docs/training_retrospective_2026-07-20.md:61`)、金标由 moonshot-v1-8k 生成、主评委 moonshot-v1-32k——数据、金标、评委同族(`stats_review.md` §7.1)。E1b 的"异源"尝试因 kimi-k2-0711-preview 探测 404 兜底 moonshot-v1-8k,实为同族弱异源(`experiments/e1/e1_report.md` E1b 注);工程启示③:"评委稳健性声明必须标注评委家族谱系;换了个同族小弟不算异源验证"(`assessment_report.md` §E1b)。【已证实】内部溢价分析虽不支持"同源偏袒主导"(v3 Moonshot 含量最高但 judge 溢价反降,`stats_review.md` §7.2),但 W3 的正式结论是同源风险"结构上存在、内部数据无法排除",唯一排除路径就是真异源重评(`stats_review.md` §7.3);评估报告已将"真异源评委终审"列为投稿前强烈建议必做项(`assessment_report.md` §5.2)。【文献支持】自我增强偏差(self-enhancement bias):模型偏好自己家族的输出(Panickssery et al.,`eval_methodology_research.md:45`)。

**风险与缓解**:风险①——GPT/Claude API 需要新 key 与预算;缓解:600 裁决 × ~2k token,成本极低(评估报告原话"API 成本极低",`assessment_report.md` §5.2),列入 v5 预算开放项请 Owner 裁决(见 §9-③)。风险②——异源评委 rubric 理解差异引入新噪声;缓解:异源评委只做 overall 四维 rubric 点值评分(与主评委同 rubric 文本),不做 pairwise,先做 40 题翻转率冒烟(决策 4.1)。

### 决策 4.4:长度控制——v5 决策门必须包含"长度归一化 judge"与"同长度桶对比"双臂

**决策**:v5 judge 轨从单臂升级为双臂,两臂均为决策门输入:
- **臂 A(长度归一化 judge)**:rubric 增加显式反冗长条款——"仅评估信息正确性、TRIZ 方法运用与结构完整性;回答长度本身不构成加分项,冗余重复内容在 completeness 维度扣分";judge 输入不截断(消除 1500 字符截断不对称);
- **臂 B(同长度桶对比)**:将全部响应按字符数分桶(<500 / 500–1500 / 1500–3000 / >3000),只在同桶内做模型间配对比较;v5(~300 字符)与 base(~3250 字符)不同桶时,报告"无同桶配对"并以臂 A 为准。
决策门引用 judge 数字时必须同时给出臂 A 与臂 B 结果;两臂结论冲突时冻结判定并启动人工抽检 20 题。

**论证**:【已证实】长度混淆是 E0 后悬而未决的最大解释威胁:base 均长 3250 字符 vs v2/v4 ~300 字符(~10 倍差),judge completeness 维度天然偏好长答,E0 −0.30 [−0.46,−0.14] 可能含冗长偏差成分;E0 报告明确将"长度控制后的公平对比"列为待办②(`experiments/e0/E0_report.md` §6),评估报告风险 5 确认"base 质量更高与 judge 偏好冗长两种解释目前无法完全分离"(`assessment_report.md` §七-5)。【已证实】旧 judge 输入截断 1500 字符造成不对称(base 仅 ~46% 可见,v2/v4 100% 可见)——该不对称在旧方向下压低 base 分,即 base 真实优势可能比 −0.30 更大(E0 §4.5-1);不截断是消除测量 artifact 的最低要求。【已证实】反方证据:gold 中 judge 分与响应长度 Spearman r=0.035~0.118,p>0.23(全部版本)——长度偏袒在 v2/v3/v4 区间内不显著(`stats_review.md` §7.2),但这不排除"10 倍长度差"极端区间的偏差,故双臂设计而非直接采信"无长度偏差"。【文献支持】长度/冗长偏差:控制内容后长回答仍被偏好(Saito et al.,`eval_methodology_research.md:44`)。

**风险与缓解**:风险①——臂 A 的"反冗长条款"可能过度矫正,把合理的长答压分;缓解:臂 A rubric 先在 v4 既有缓存(base_goldfix/v2/v4)上试跑,若 v4−base 差值从 −0.30 移动超过 ±0.15,人工抽检 20 题校准条款措辞后再上决策门。风险②——臂 B 桶内样本量小(v5 全部落 <500 桶,base 全部落 >3000 桶,同桶配对可能为空);缓解:这正是设计意图——显式暴露"两模型无同长度可比样本"这一事实,而不是让 judge 在不可比样本上假装可比;臂 B 同时用于 v5 vs v2(同 ~300 字符,同桶,高功效)这一关键对比。

## 5. 金标集扩充:100 → 200 题

### 决策 5.1:扩充至 200 题,新增 100 题作为冻结扩展层,原 100 题保持钉住不动

**决策**:金标集从 100 题扩至 **200 题**:原 100 题(`v4_gold_001`–`100`)作为"钉住层"一字不动,保证与 v1–v4 全部缓存可比;新增 100 题(`v5_gold_101`–`200`)按 6 子集等比扩充(principle +20 / contradiction +20 / ariz +20 / case +15 / concept +15 / innovation +10),生成流程沿用 v4 金标管线(Moonshot 生成 + 规则校验 + 人工抽检 10%),新增题必须通过金标去污门(对 v5 训练语料 J≥0.5 丢弃)——去污门必须对**v5 新语料**重跑,不得沿用 v4 去污结果。

**论证**:【已证实】功效现状:n=100 时金标 overall 只能分辨 ~10pp 级差异——v4 vs base judge 轨 MDE 0.279、kw 轨 MDE 0.088;v4 vs v2 judge 轨 MDE 0.176、kw 0.048(`stats_review.md` §6.1);pass 率 McNemar 只能分辨 ≥18.6pp(kw)/ ≥21.5pp(judge)(`stats_review.md` §6.1)。【已证实】子集现状:n=15–20 的子集 judge MDE 0.374–0.774,全部子集级结论只能描述性(`stats_review.md` §6.2、§6.4-3);且 100→102 几乎无改善(0.279→0.276),小修无意义(`stats_review.md` §6.1)。【推断】n=200 的目标分辨率(按 MDE ∝ 1/√n 由实测值外推):overall judge MDE 0.279×√(100/200) ≈ **0.197**,kw MDE 0.088×√(100/200) ≈ **0.062**,McNemar 可分辨差 ~13–15pp;子集层面 n 翻倍后 judge MDE 仍 ≥0.26–0.55,**子集结论依然描述性**——扩充的真实收益在 overall 与 McNemar 分辨率,不在子集升级,报告中须如实说明。若 Owner 要求子集级推断力(judge MDE ≤0.3),需每子集 n≥65(总 n≥390),成本超出一个工作日的评测预算,列为开放项(§9-①)。

**风险与缓解**:风险①——新题与旧题难度分布漂移,overall 差值混杂"题目构成变化";缓解:所有 v5 对比同时报"钉住层 n=100"与"全集 n=200"两个口径,决策门以全集为准、钉住层做稳健性核对,两口径结论冲突时冻结并归因。风险②——新题生成引入同源污染(金标生成器与训练数据生成器同族);缓解:去污门对 v5 语料重跑 + 人工抽检 10% + 报告中声明同族局限(与决策 4.3 的异源终审联动)。

**风险与缓解**:风险①——生成题质量参差;缓解:规则校验(答案词必须在参考答案中出现)+ 人工抽检 10%,沿用 E6 设计卡。风险②——12 类×20 后单类 n=20,类级结论仍描述性;缓解:探针决策门只看 overall 退化,类级只作归因线索。

## 7. 决策门 2.0

### 决策 7.1:决策门 2.0 数值判据(全部可机检,无自由裁量)

**决策**:v5 替代 v2 发货,须**同时**通过以下 7 道判据(评测集 = 金标 200 题 + 探针 120 题;锚点 = base_goldfix 谱系干净锚点,经 §1.3 重验):

| 门 | 判据 | 数值阈值 |
|---|---|---|
| G1 | judge 轨 vs 干净 base(长度归一化臂 A) | v5−base overall 差值 CI 下限 **> −0.15**(即显著优于 v4 的 −0.30 水平;臂 B 同长度桶结果须不矛盾) |
| G2 | judge 轨 vs v2(增量必要性) | v5−v2 overall 差值 CI 下限 **> −0.05**,且 judge/kw 至少一轨显著为正——否则无增量,保留 v2 |
| G3 | 关键词轨退化禁令 | 任何子集 v5−v2 kw 差值 CI 上限 **< 0**(显著退化)→ 触发 E2 式归因;真缺失 → 拒绝发货;伪影 → 语义轨裁决后可放行 |
| G4 | 子集退化容忍度 | n<30 子集的退化一律标"描述性",不独立否决;但该子集 judge 轨同方向显著为负时,与 G3 合并视为真退化 |

| G6 | 通用探针回归门 | v5−v2 探针 overall 差值 **> −5pp**(120 题分辨率内,MDE ≈4.7pp) |
| G7 | 双轨反向熔断 | 任一维度两轨显著反向 → 默认回滚 + 归因实验,禁止单轨翻盘 |

**论证**:【已证实】阈值来源逐条对账——G1 的 −0.15:v4 与 v2 对干净 base 的 judge 差分别为 −0.30 [−0.46,−0.14] 与 −0.29 [−0.42,−0.16](E0 §4.3),v5 的立项前提就是把这个差距压缩一半以上,−0.15 是"v5 有实质进展"的最小可接受声明;n=200 时 overall judge MDE ≈0.197(§5.1),−0.15 的下限判定在功效边缘,故 G1 同时要求臂 B 不矛盾。G2 的 −0.05 与"至少一轨显著为正":直接来自 v4 教训——v4≈v2(judge −0.01 [−0.13,+0.11]、kw +0.008 ns)无增量故不替代(E0 §4.4);kw 轨 n=200 MDE ≈0.062,±0.05 在 kw 轨实用等价界内(沿用 `stats_review.md` §6.4-1 的 ±0.05 等价界)。G3/G4:沿用 v4 决策门"显著退化子指标"机制(E0 §4.4 曾以 keyword/concept_explanation 显著退化触发保留 v2),并补上 E2 教训(退化须先归因,`assessment_report.md` §E2)与功效现实(n<30 子集 MDE 0.26–0.55,`stats_review.md` §6.2)。G5:E3 案例(E3' v4 vs base rubric +0.083 [0.033,0.142] 显著 vs kw 漏判率 31.7%)。G6:E6 设计目标(§6.1)。G7:工程启示⑦原文"两轨反向时默认回滚并启动归因实验"(`assessment_report.md` §三)。

**风险与缓解**:风险①——G1 阈值 −0.15 在 n=200、MDE≈0.197 下可能永远判不出"显著优于 −0.15";缓解:若 v5−base 点值 > −0.15 但 CI 下限未过线,允许启动"加赛":扩充钉住层外再加 100 题(n=300,MDE≈0.161),或接受"G1 降级为描述性通过 + 其余门全过"由 Owner 终裁(§9-④)。风险②——7 道门联合假阳性率上升;缓解:各门检验的是不同构念且方向多为"防退化"(保守方向),不做多重性校正,但报告中列出各门单独 p 值供审计。

### 决策 7.2:用 v4 案例演示决策门 2.0 的判定过程

**决策**:将 v4 既有数字代入决策门 2.0 做回溯验证,演示新门的行为(作为门设计的验收测试)。

**论证(演示)**:【已证实】v4 代入结果——

- **G2**:v4−v2 judge −0.01 [−0.13,+0.11],CI 下限 −0.13 < −0.05,且两轨均无一轨显著为正 → **G2 不通过**(无增量)。
- **G3**:CE 子集 v4−v2 kw −0.083 [−0.149,−0.023] 显著退化 → 触发归因;E2 已判真缺失 8 词次、伪影 0 条 → **G3 不通过**(真退化)。
- **G7**:CE 子集 kw 显著为负 + judge 持平(+0.07 [−0.2,0.33] ns),非"两轨显著反向",不熔断,按 G3 流程处理。
- **综合判定:拒绝 v4 替代 v2(保留 v2),理由链 = G1 未达 + G2 无增量 + G3 真退化**——与 E0 干净锚点重判的实际结论一致(E0 §4.4"保留 v2"),但理由更完备,且新门额外产出一条旧门没有的行动项:"judge 轨 −0.30 含未分离的长度混淆,须补长度控制臂"(E0 §6 待办② 正是此项)。回溯验证通过:新门在已知案例上判对、且判得更透明。

**风险与缓解**:风险——回溯验证只有 v4 一个正例(拒绝例),缺少"应发货却误拒"的反例测试;缓解:v2 vs base(eval2 口径 judge +0.0736 [0.0310,0.1162] 显著,`evidence_table.md` ②-C)可在 v5 首轮评测时作为"准正例"代入门内做第二轮回溯,验证门不会在真实进步案例上误拒。

## 8. 统计纪律(全部强制,写入评测脚本断言)

### 决策 8.1:八条统计纪律

**决策**:
1. **配对 bootstrap 10,000 次,seed=42,实现钉死 stdlib `random.Random(42)` 逐差值重抽样**(与 eval_harness 同实现);禁止换用 numpy RNG——两者存在千分位 CI 差异(kw 轨 [0.1297,0.2520] vs [0.1321,0.2537]),复现必须同实现(`stats_review.md` §1.2 注)。
2. **McNemar 精确双侧检验**用于 pass 率配对比较(沿用既有实现,复算已验证至 p=1.6979681549678105e-12 逐位一致,`stats_review.md` §1.2)。
3. **Wilson 95% CI**用于一切比例(胜率、pass 率、不一致率、漏判率)。
4. **seed 与配置入报告 meta**:每次评测报告记录 RNG 实现、seed、judge 版本、温度、截断长度、锚点缓存 tag。
5. **子集结论标"描述性"**:n<30 的子集结果一律标注"描述性(n=X,MDE=Y)",不得进入摘要的推断性陈述(`stats_review.md` §6.4;`eval_methodology_research.md:56-61`)。
6. **MDE 随 CI 同报**:每个差值 CI 旁标注该配对在当前 n 下的 MDE;"未发现显著差异"与"等价"严格区分——CI 半宽 >±0.05(kw)/ ±0.13(judge)时禁用"等价/相当"措辞(`stats_review.md` §6.4-1)。
7. **功效不足清单制**:每份报告附"本次功效不足的结论清单"(仿 `stats_review.md` §6.4),列出哪些"不显著"是功效不足型。
8. **逐题明细落盘**:全部逐题分数(kw/judge/配对差值)以 jsonl 落盘,与报告数字可逐位对账(沿用 `e0_stats.json` / `stats_results.json` 模式)。

**论证**:【已证实】纪律 1–3 的全部实现已在 v4 金标与 E0 中经过独立复算验证,100% 可复现(`stats_review.md` §1 总判"原报告数字 100% 可复现");纪律 5–7 直接来自 W3 功效分析的三条结论("v4≈v2 是功效受限措辞""子集 n=15–20 仅描述性""不显著均为功效不足型",`stats_review.md` §6.4)与文献经验法则(5pp 分辨率需 n≈400+,10pp 需 n≈100,`eval_methodology_research.md:61`);纪律 4/8 是 E0 事故的正面遗产——E0 能定位污染,正因为逐题明细与 meta 齐全(`experiments/e0/E0_report.md` §4 的数据可用性)。

**风险与缓解**:风险——纪律过细导致执行者绕过(如为省事用 numpy 复算);缓解:评测脚本内置断言(bootstrap 实现指纹校验:用固定玩具数据跑 100 次重抽样,比对预存哈希),报告生成器自动插入 MDE 与"描述性"标注,不依赖人记。
